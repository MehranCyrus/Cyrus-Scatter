# Cache host validation research and evidence

This note separates documented SDK behavior from actual Cyrus Arrange observations. It supplements [the implementation research](../CACHE_IMPLEMENTATION_PLAN.md).

## Primary SDK sources

The [Max 2027 SimpleObjectBase reference](https://help.autodesk.com/cloudhelp/2027/ENU/MAXDEV-CPP-API-REF/class_simple_object_base.html) describes the procedural mesh and its validity interval, and exposes mesh evaluation/build/conversion operations. A procedural object's evaluated validity is a contract supplied by that object. Whether it changes during this plugin's first capture must be measured; the documentation alone does not prove that this explains any observed rejection.

The [Max 2027 IRefTargContainer reference](https://help.autodesk.com/cloudhelp/2027/ENU/MAXDEV-CPP-API-REF/class_i_ref_targ_container.html) permits reading the actual changed item and its index only while handling the container notification. The observer therefore copies bounded numeric event details during the callback, rather than retaining the temporary payload or deferring access to these getters.

The [Max 2027 INode reference](https://help.autodesk.com/cloudhelp/2027/ENU/MAXDEV-CPP-API-REF/class_i_node.html) and locally installed `inode.h` describe `GetObjectTM` as context-dependent, returning a before- or after-WSM frame. The explicit `GetObjTMAfterWSM(TimeValue, Interval*)` supplies the final-pipeline frame and its validity. Transform evaluation may invalidate borrowed evaluated mesh data, so query order also matters. After native36's measured coordinate failure below, working capture/key source now queries this explicit frame before a fresh evaluated-object borrow. This source correction still needs successor runtime qualification; an unchanged node transform alone is not sufficient evidence of correct WSM capture.

## Actual first integration result

Full native29 passes eleven CTest targets / 110 reported cases. In its private Max processes, the new cache harness fails while Analyze is running with reuse disabled, and the existing artist workflow fails during Generate's geometry capture. Both processes loaded the exact candidate DLL pair; both private-profile and artist-preservation checks pass. These are product regressions, not successful cache qualification.

The first errors combined state, dependency and exact-key comparisons. Their text could not distinguish a callback event from scope/transform/evaluated-validity drift. Native30 therefore adds separate guard messages and a single fixed first-invalidation record in the active command. Event capture uses no strings, files, mesh operations or allocations; a failed guard formats the explanation afterwards. It also reports the first differing exact-key component. No observation filter is loosened for this diagnostic attempt.

The failed runs remain `build/host-cache-01` and `build/host-cache-29-workflow`. A successor must first pass unchanged cold behavior, then prove real publication-time input changes are still rejected. Enabled-hit timing is downstream of these correctness gates.

## Native30 diagnosis

Both `build/host-cache-02` and `build/host-cache-atomic-01` identify a real temporary-observer construction notification: `first=commandWatch`, `message=0x50`, `part=0x800037ff`, `constructing=1`, changed item index zero. The first geometry/dependency epochs advance from 3 to 4; by the command's later ticket snapshot, dependency epoch 46 is already current. The active scope's first-invalid flag correctly remains set, explaining why an equal current epoch alone did not authorize the command.

This evidence identifies self-generated reference-container setup as the first failure. It does not establish a procedural validity mismatch. The fix under review builds the container before subscribing its command observer, while preserving existing document observation and final input-scope validation. It must not reset an invalidation flag or ignore all change messages during capture/publication. The callback harness's baseline fails before callback registration, so its twelve case failures are not evidence that real publication callbacks ran.

## Native31 host and harness distinction

Attach-after-fill restores ordinary analysis/generation in the real host. The atomic harness reaches real one-shot callbacks in both disabled and enabled modes. Input edits reject the successor before acceptance, existing nodes/poses/groups/revision survive, and observed dirtiness/epochs survive cancellation. Caught same-setup nested Generate rejects while its outer generation completes. These are partial assertions only: ten cases then stop on a test helper error, and the general cache harness hits the same error during its physical oracle.

The [2027 MAXScript Array Values documentation](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/MAXScript-Language-Reference/Collections/Collection-Types/GUID-A5B54C67-BFDD-45C0-9D6B-E6869817282A.html) explains the reproduced result: mapped `copy array` returns `OK`, whereas `copy array #noMap` returns a shallow array copy. The two helpers only append to the copied outer list, so a shallow copy is sufficient; no nested geometry is edited. The source correction preserves all assertions and requires fresh complete runs.

The same reference warns that array string formatting abbreviates long collections. New test hardening will use strict element comparisons for complete warnings, member IDs and diagnostic arrays instead of inferring full equality from printed strings. Physical world-bound comparisons retain their explicitly declared numeric tolerances.

## Native32: successful callback gate and a separate between-command defect

`host-cache-atomic-03` completes 233 assertions with no failures. Actual one-shot node-creation callbacks edit furniture, obstacles, accessory geometry and group membership during publication; those successors reject while preserving the previous publication. An Undo-off source edit remains pending after cancellation. Caught same-setup nested Generate rejects while its outer operation completes. Both disabled and enabled reuse modes are exercised. Exact loaded binaries/private profiles and artist-profile preservation pass. The stronger complete-array successor still needs a fresh run.

`host-cache-04` completes 314 assertions with 17 failures. Its new Preview-only fixture identifies a different defect: after the initial authored setup, a new board is attached to a furniture group and discovered only by Preview. No Generate, Analyze, Commit or authored setter refreshes durable descendant references afterwards. Changing that board's height from 20 to 80 mm changes its independently measured support top from 820 to 880 mm without changing its node transform or parent. The dependency ticket nevertheless stays unchanged and Commit accepts the old Preview. A cache key's reevaluation is not a substitute for keeping a retained Preview's newly discovered inputs observed between commands.

The source correction moves the complete bounded expanded observer into transient Document ownership. A new command stages a replacement while the preceding watcher remains active. SDK references are released at safe ordinary boundaries after active publication/cancellation, not inside notification handlers. The observer stays outside serialized reference slots, authored document state, Undo and the numerical cache. Known stale descendants in the last authored derived-reference container can be ignored only against a complete authoritative current observer; unknown sender payloads retain conservative invalidation. Owner/self/ancestor cycle rejection is explicit because the C++ ownership edge is not visible as a serialized Max reference.

The installed Max 2027 SDK `ref.h` (lines 1947–1955 in this installation) and the [ReferenceTarget page](https://help.autodesk.com/cloudhelp/2027/ENU/MAXDEV-CPP-API-REF/class_reference_target.html) contain a conflicting return-value description for `TestForLoop`. Native33 followed that sentence and incorrectly rejected an ordinary valid bound input in `host-cache-05` (2 / 3). The shipped executable examples establish the usable convention: `samples/controllers/attach.cpp` accepts `REF_SUCCEED` before `ReplaceReference`; `path_cnstrnt.cpp` and `link_cnstrnt.cpp` likewise accept it before adding a target. Most directly, `samples/maxscript/mxsagni/avg_dlx.cpp` implements `refs.dependencyLoopTest` by returning true when the exact native call returns `REF_FAIL`. The successor therefore rejects results other than `REF_SUCCEED`, retaining explicit setup/ancestor checks. Normal and actual negative-cycle host cases are required; successful compilation alone did not catch this SDK contract error.

Queue identities use animatable handles plus pointer identity, and staged node references are checked immediately after SDK calls before dereferencing them. This source review addresses callback lifetime risks; it is not evidence that every third-party notification path has executed.

Another source review found that removing the native ownership attribute may leave an Undo-held document's owner monitor non-null. A safe Live boundary now verifies the actual owner attribute association before scheduling work, with a registry snapshot and native lifetime pins during deferred reference release. The proposed real custom-attribute detach/Undo test will establish that a retained detached document cannot create ghost output and that explicit regeneration works after Undo restores legitimate ownership.

Separate harness repairs remain explicit: the cold/hit work comparison now establishes equal previous placement/group state, because validation of prior records is counted as solver work. Actual UI Reroll poses remain directly compared with the forced-cold result, while complete statistics/work are compared against a nonpublishing Preview with matching prior state. Detach opens the owned group first, as required by the [Max 2027 group-method reference](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Node-MAXWrapper/Node-Common-Properties-Operators/Node-Common-Methods/GUID-FB6EA335-79C3-437E-8DD8-68B56981F771.html), and verifies real membership removal. These changes do not relax the stale-Preview rejection or physical-placement assertions.

## Boundary measurement correction

Native35's boundary run reports 1 pass / 16 failures because every case stops at its physical oracle's analytic prerequisite: an original board at 500–530 mm is measured at 1000–1030 mm. The helper incorrectly multiplies a MAXScript world snapshot by the object's transform again. The [2027 geometry export tutorial](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/How-To-Practical-Examples/How-To-Read-Write-Geometry-Data/GUID-38562330-1435-4112-9265-DE965319A2F2.html) identifies snapshot vertex positions as world coordinates, including space-warp evaluation. Shipped SDK `common_funcs.cpp` implements `getWorldStateMesh` by copying evaluated geometry and applying `GetObjTMAfterWSM` once. This differs from reading a raw local object mesh.

The correction retains a disposable collapsed snapshot and reads its world-snapshot mesh through `meshop.getVert` without a `node:` argument, multiplying only by the millimetre conversion. [Meshop Vertex Methods](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Editable-Meshes-Splines-Patches/Editable_Mesh-and-TriMesh/GUID-483BD7AC-832C-442C-8820-65EEC52815C4.html) documents that this raw mesh form does not transform vertices through the current coordinate system. The analytic fixture prerequisite is preserved, and transformed/pivot/context controls will validate the measuring helper before the host boundary cases. This repair changes the independent test oracle, not the plugin's native capture convention.

## Native36: calibrated WSM failure and separate harness limits

`build/native-arrange-36/receipt.json` passes eleven CTest targets / 110 reported cases. Its actual boundary run, `build/host-cache-boundaries-04/receipt.json`, fails with **94 passes / 22 failures**. Process exit code zero is not a suite pass. Both loaded module paths and binary hashes match the candidate, and private-INI and artist-profile preservation checks pass. The original failed receipts and logs remain unchanged.

The independent world-coordinate controls now pass all six prerequisites: literal translated bounds, a quarter-turn, a genuinely shifted pivot/object offset, unchanged world vertices after that pivot change, caller-coordinate-system independence and cleanup of disposable scene nodes. The original board is measured at 500–530 mm. Binding a real planar Displace space warp with 40 mm strength moves every measured board vertex to 540–570 mm while its node transform remains translated by 500 mm. The log prints both measured bounds and node/object transforms.

Against that calibrated 570 mm support top, native inspection reports a region at **1070 mm**, and all four published accessory contact positions are at **1070 mm**. This establishes a product coordinate defect in evaluated WSM capture, rather than merely a cache-disposition discrepancy. The prior context-dependent `GetObjectTM` path applies an extra 500 mm translation to geometry already transformed by the world-space pipeline. Native capture, key construction and physical placement must agree on the explicit final-pipeline frame.

The reviewed source correction is promoted at four evaluated-geometry boundaries: inspector numeric capture, arrangement numeric capture, visual capture's mirror/normal frame, and the geometry key. Each now queries `GetObjTMAfterWSM` before obtaining a fresh `EvalWorldState` object; numeric/key paths use the returned transform-validity interval. The inspector's ordering also avoids borrowing a pipeline object before a transform query that may invalidate it. Authored source-axis/locked-output transform checks remain separate. No dependency, validity, final-key or publication guard is relaxed. **This promoted correction is not yet runtime-qualified on a successor pair.**

### Scene-producing oracle actions are a confounder

The native36 measuring helper still creates and deletes a collapsed `snapshot` scene node while checking physical geometry between purported cold/hit operations. The run records an expected hit becoming `cold/empty`, and the detached-Live case stops at its clean-state prerequisite. These are uncontrolled scene actions in the measuring path. The log does not isolate which notification or lifecycle event caused each invalidation, and does not prove that the helper edited the source's authored mesh. In particular, printing a source as `$Editable_Mesh` after WSM evaluation is insufficient proof of base-object mutation: the [node inspection documentation](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Node-MAXWrapper/Node-Common-Properties-Operators/GUID-D1D7EB56-A370-4B07-99B4-BC779FB87CAF.html) distinguishes evaluated world-state inspection and snapshot behavior.

The successor oracle is prepared to use `snapshotAsMesh source renderMesh:false` directly, then raw `meshop.getVert` on the returned mesh value without a `node:` argument and without another object transform. It creates no scene node. It also checks that scene nodes, dependency ticket, full setup summary and cache diagnostics remain unchanged around measurement. Separate `caInspect` checks are prepared to compare source world bounds and triangle counts. Those strengthened nonmutation and capture checks remain pending actual execution.

### Native owner-attribute access remains an unqualified boundary

The native-cycle/detached-owner fixtures expose two separate MAXScript API mistakes. `custAttributes.count setup baseObject:false` returns zero even while native setup commands resolve the attached owner. The [custAttributes management reference](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Custom-Attributes/GUID-0A1E08F8-A8C5-4737-AA6F-39194AD16559.html) describes that enumeration as scripted custom attributes; this result cannot establish that the native owner is absent. The attempted `(classID value)` call also resolves an undefined local in the failing stack. The documented operation is the MAXWrapper [`.classID` property](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/MAXWrapper-Value/GUID-95453E22-A022-4543-B31C-A052CECD3598.html).

The prepared replacement uses the generic [`setup.custAttributes` virtual array](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Custom-Attributes/GUID-695C13A5-B461-4520-8540-47D18CA23AB0.html): enumerate/index actual values, identify the unique owner by `.classID`, and read its actual Document with one-based `refs.getReference`. For detach it uses documented `deleteItem` with the actual attribute value under ordinary Undo, rather than altering any native reference slot. Installed SDK MAXScript wrappers accept native `CustAttrib*` values and convert the wrapped reference target for read access. The generic path is source/documentation-backed, but native enumeration, deletion/Undo and the actual negative-cycle fixture still require host proof. No guessed `getContainer` command, reference-slot replacement or artist-facing test hook is introduced.

The OSM/retessellation case also stops at an unconditional book-row prerequisite after producing four physically valid ordinary props. A valid ordinary result does not prove that this relational fixture formed a row, so that prerequisite must be diagnosed explicitly. No WSM/merge/owner/cycle completion is inferred from partial assertions. Reuse remains **off by default**; a new exact source/native/UI pair, complete host boundaries, all functional suites, serial paired performance and installer qualification are still outstanding.
