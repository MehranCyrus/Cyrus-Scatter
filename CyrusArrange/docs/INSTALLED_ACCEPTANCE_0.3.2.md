## Ownership and failure behavior, declared before edits

The installer owns an immutable version/payload directory under the mapped
user-script directory and publishes only the startup loader, macros and native
plugin registration after complete payload verification. Existing preimage,
rollback, tamper, idempotence and private-profile checks remain intact. This
change updates its artist-facing success instructions, not its transaction.

The second owned normal Max process must discover that actual installed loader,
native pair and macros by startup. The test must not fileIn loose product scripts
or call a replacement UI factory to simulate installed discovery. Installed
macro actions create/focus the native icon/modifier. A transient native-hosted
MAXScript custom attribute displays the one Modify view; the native Document
owns settings, source capture, minimum policy, generation and Undo state.

The test owns only a disposable scene, a table and two small original source
models/materials. Its bounded geometry snapshots are test evidence and are
released after copying; they do not calculate production placements. Visible
drafts stay transient until the actual Generate handler invokes the native
atomic command. Invalid drafts must retain the prior accepted document, seed,
revision and output nodes. One successful Generate is one Undo/Redo operation.
Closing the installed page must release its owner binding. Save/reopen keeps
accepted state and the installed page mounts passively before explicit Generate.

No artist profile, process or scene is modified. No Max launch, build, package
or installation is performed by this editing subtask. Parent-owned installer
runner and packager retain authority for actual archive hashes, private-profile
mapping, loaded module paths, process identity, normal exit and final acceptance.
