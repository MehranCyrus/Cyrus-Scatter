# Release UI test mapping for 0.3.2

Source maintenance status: the five suites below have been ported for the
current native Modify view. Their final exact-source Max 2027 runs are still
required. This document and the delimiter audit under
`build/release-ui-ports-static02/receipt.json` are not execution evidence.
Earlier unified-view passes do not execute or qualify these edited files.

The public workflow is receiving geometry or a spline, inline original props,
Quantity/Fill, optional scale and clearance, then Generate. Generate applies
the drafts in one native transaction and normally chooses a fresh seed.
Repeat seed exposes the exact integer entry. These suites do not reinstate
Home, Advanced, Props, category, support or rules popups.

## Deliberately retired assertions

The former furniture/category dropdown, name suggestion buttons, Apply button,
Advanced interoperability and Home/Advanced dirty-field merge describe removed
artist UI. Their old control names are not retained as acceptance requirements.
The relevant replacement is a single current view with pending inline values,
explicit Generate, native source eligibility by physical fit, and owner/GUID
guards. Native saved descriptive metadata is still checked where applicable;
it must not become a required source eligibility filter.

The explicit legacy `caCreateSetup` API retains Fill because its eleven-field
settings transport density. Current `caCreateArrangement` retains Quantity100.
The bulk fixture intentionally uses the legacy constructor for its source and
catalog history, then explicitly switches the actual current amount dropdown
to Quantity before setting Copies8 and Min8. It does not infer that entering
an inactive Copies field changes placement mode.

The old standalone Props view was allowed to remain active after selection
closed Modify. Current Add requires a pinned actual Modify stack, while the
shared picker completion handler accepts explicit selected nodes for tests.
Retired CA dispatch, callback-driven closure and Document replacement preserve
the underlying stale-owner/reentrancy requirements. No test claims to automate
the viewport `pickObject` gesture. Group tests use the same `#groupProps`
completion command as the real picker with explicit original nodes.

The old Preview/Commit popup's exact sentence formatting and old Apply/Live
error wording are retired UI assertions. Current inline placed/requested/
unfilled/seed text is checked in the simple/bulk suites; native preview
publication/failure retention and raw Live remain checked in workflow and
their dedicated required suites. The current default does not expose another
Live or Preview settings popup. These ports must not be described as proving
the former popup formatting or automatically enabling Live for artists.

The prior separate inspector entry is intentionally different: inspect_tests
re-fileIns `scripts/CyrusArrange.ms` immediately before invoking its diagnostic
`caShowUI position:` function. It qualifies that isolated diagnostic producer,
not an installed public inspector popup. Installed public aliases are loaded
last from ArrangeModifier and focus native Modify. Installed startup has its
own independent final acceptance.

## Complementary required current coverage

The retained four suite names are not substitutes for
`arrange_unified_modify_tests.ms`, `arrange_status_undo_tests.ms`, or
`arrange_legacy_minimum_workflow_tests.ms`. Those add actual inline layout,
minimum/scale drafts, path/obstacle sections, status hydration, protected legacy
row transition and current transactional behavior. Dedicated geometry, base,
shelf/stair, compound collision, road, imported-device and recovery producers
retain independent actual-mesh export verifiers and negative controls.

Raw lifecycle, migration, cache/preview, composition, materials and real-model
tests also remain required by the final package policy. A mapping or a source
check does not satisfy a missing receipt. Package qualification must bind each
required completed host run to the exact final source map and both loaded
native module hashes.

## Validation and limits

The source-only audit checks balanced string/comment/delimiter structure and
records the five script SHA256s. It does not parse MAXScript, execute native
handlers, launch Max, build, install or package. Its static assertion-site
counts are not pass counts; loops and prerequisites change executed totals.

Final host acceptance must use fresh owned **normal Max2027** processes for
all four current UI ports. The runner owns serialization, exact input/loaded
identity and artist-profile guards. No artist scene/profile or installation
is changed by these fixtures. Any failure must preserve its original receipt
and be resolved with a fresh source/build/run identity as applicable.

These fixtures do not prove mouse-create/picking gestures, general scene
quality, arbitrary DPI setups, rendering or performance. The one bulk intake
stopwatch remains an observational timing for that command, not a benchmark.
Cache performance and private installer/automatic startup qualification remain
separate final gates.
