## Ownership, invalidation and recovery

The native Document already owns independent obstacle references and the saved
clear-front-approach flag. The view will show one Keep clear list, Pick obstacles,
Remove obstacle, the optional Clear approach checkbox, and existing placement
protection commands. Receiver geometry is always collision-tested; independent
obstacles never become support surfaces. No automatic whole-scene scan.

Picking/removing an obstacle is an explicit native Undoable reference edit like
adding a prop. It retains current output, marks relevant inputs dirty, and does
not analyze meshes or solve in Manual mode. Reading/opening the section is a
bounded cached-reference query only. Missing references remain removable.
The native intake rejects receiver, prop, generated-output, path and owner-role
overlap before committing. Complete groups are expanded natively under existing
4096-node bounds. The view only transports at most 4096 root references/labels;
it never transports geometry or adds a retained mesh/collision cache.
Native Add merges normalized roots while preserving missing reference slots.
Native Remove consumes one row plus its cached Document revision, rejects stale
rows, and can remove one missing slot without losing the others. Both commands
use the same bounded scope validator and native commit/Undo path as replacement.

Clear approach is a view draft until Generate, then commits with settings,
minimums, seed and outputs through the existing atomic C++ generation path.
Failed generation retains all accepted values and outputs. Adding obstacles,
refreshing or Undo must preserve genuine uncommitted approach and placement
drafts, while accepted values follow native state. Group creation can close the
edit context; its explicit same-owner continuation must restore this draft too.
Retired bindings and late picker returns must not mutate another arrangement.

No saved schema change or new geometry resource is needed. The staged native
settings gain one optional boolean. Existing minimum-generation API arities
retain their prior behavior; a final optional boolean carries the Modify draft.
Undo/history/resource ownership stays in the native Document. Optional checks
remain collapsed. No artist installation or existing-session mutation.
