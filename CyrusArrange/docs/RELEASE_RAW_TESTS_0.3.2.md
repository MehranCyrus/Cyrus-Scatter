# Raw API acceptance during the geometry-first release

The native document remains the owner of recipes, references, output and history.
These test maintenance changes do not change production settings, caches or saved
schemas. A failed host keeps its receipt; a corrected fixture runs in a new owned
process against a newly frozen complete source map.

The released artist entry points focus the single Modify panel. A few retained
raw API fixtures deliberately re-fileIn individual diagnostic scripts to exercise
their old bounded editing adapters. Such bootstraps do not qualify an installed
popup or the current artist workflow. Current unified and installed tests provide
that acceptance separately.

Historical furniture labels and category masks/count caps remain serializable
metadata. They no longer decide which selected prop may fit. The region fixture
therefore checks descriptive-mask independence, while explicit exclusion, density
zero, support ownership, stacking permission, front direction, persistent IDs,
selective regeneration and failure retention remain meaningful physical controls.
Its clustered-neighbor regression uses exclusion and zero density, rather than a
retired category-denial rule. The book-row fixture checks raw explicit row layout
and physical member relationships without treating a historical category cap as
an output limit. Current Quantity and per-prop minimum tests own exact requested
counts. Front-access defaults must be category independent and off until requested.

These are planned test contracts, not passes. Final source-pair Max execution,
independent mesh proofs, installer/startup and performance evidence remain required.
