# MCP operation acceptance baseline

24 October 2026. Implements the M00 operation decomposition for the current 36-family catalog and 333 local controls. These are domain operations, not a proposed one-tool-per-row API. A closed proposal may batch compatible operations into one approved transaction. Local file picking and local consent remain artist actions. No row grants write authority merely by appearing here.

Baseline: Scatter 0.86.9.2/schema 59/CyrusUnified2, Analyzer 0.14.2, Max 2027; `feature-catalog.json` is the family/control inventory. Future native features enter the follow-up list rather than silently expanding this baseline. C16 retired background composition, C33 licensing administration and C34 experimental learning are excluded. Authoring license **denial** remains a required common gate. Renderer jobs and MCP Tasks/Apps are optional extensions; current output readiness remains required.

## Gates applied to every relevant row

- **A — authority:** typed closed input; exact enrolled references/context/configuration/publication; local proposal diff and fresh approval for writes; wrong scope, unknown IDs and stale approvals denied. Names/assets never carry instructions.
- **B — preservation:** correct ordered owner/layer/source identities; untouched settings and unrelated artist objects preserved; explicitly declared replacement/import/deletion effects; no same-name rebinding.
- **C — transactions:** one coherent native authored hold, correct commit/rollback/uncertain effects, exact-key retry, queued cancellation and own-top Undo/Redo; failed successors retain the complete previous publication.
- **D — modes:** Manual pending/current authored state distinguished from last complete publication; configure-only has no solve/upload; Live responds to relevant changes and animation; unrelated browsing/selection/time causes no static rebuild.
- **E — data:** physical units and coordinate frames explicit; candidate/accepted counts, ratios, areas and coverage have distinct meanings; actual native rows/IDs/radii verified, including empty/underfilled results.
- **F — lifecycle:** save/reopen/reconnect, missing/deleted assets/references, changed geometry, schema mismatch and manual conflicts have explicit supported outcomes; consent/authority never inferred from a file.
- **G — resources:** declared admission before expensive work, paging, peak/history memory, main-thread publication, no placement-sized unbounded scripted copies; appropriate native failure/cancellation/retention witnesses.
- **H — evidence:** matched source/package/loaded identities; intended external client schema/protocol and actual Max results. Keep offline, native API, physical UI and artist/task evidence separate. A catalog, mock pass or screenshot cannot close native behavior.

Reads apply A/B/D/E/G/H as relevant and must not calculate, reconcile containers, modify selection or grant authority. Sharing/export reads also need their exact local grant. Writes add C/F and all dependencies above. A successful aggregate row does not qualify every combination automatically.

Current source admission **L0**: one newly owned static horizontal convex task, three layers/assets/regions, 2,000 aggregate candidates, 10,000 input faces/12,000 vertices, two publication applications and eight configure-only commits. Normal calls, captures and publication paging have separate documented budgets. Broader rows must declare their supported workloads and per-field/native ceilings before acceptance; “pending admission” means required unfinished work, not an exclusion or permission to keep every feature at L0 forever. Publication inspection must resolve the known native-versus-parser per-set budget discrepancy.
