# Bounded recovery and Windows panel evidence

24 October 2026. Scoped M00/M01 increment; the full integration remains in progress.

## Changes

Selected recovery no longer calls the unrestricted general controller-state serializer. A fixed internal host reader admits values **before pymxs marshals arrays/strings into Python**. Its one snapshot-wide budget is 16,384 input cells, 262,144 native text units, 4,096 entries per array and depth eight. The explicit pending work list cannot exceed the remaining cell allowance. Primitive vectors/matrices and reference handles are copied as bounded metadata; resource geometry, placements and source appearance are not evaluated or recertified.

The existing selected-owner admission (32 children and 1,024 aggregate source rows) stays in force. Paint reference arrays are admitted before traversal; area counts and the native field registry have additional bounds. The native publication-info temporary remains subject to the native producer's existing signature/population/source limits; its values then pass the tighter recovery reader before crossing into Python. This is bounded metadata work, not a new native placement implementation or a measured universal memory/latency result.

The helper source is a constant, internal MAXScript function. No scene text, property value or model-supplied program is interpolated into it; models have no execute tool. Unsupported values fail recovery review rather than producing an incomplete approved witness. One successful review does not certify the entire scene or renderer/source appearance. Native reference content can change independently of its handle; those appearance/geometry limitations remain visible in the dialog.

Known commit evidence now also retains `configuration_id` before receipt serialization. Selected review distinguishes configuration agreement from publication-generation agreement. This matters when configure-only commits settings but intentionally keeps the old publication generation and rows.
