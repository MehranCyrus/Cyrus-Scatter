# Focused 0.86.9.1 acceptance

Run host scenarios in **Max 2027 only**, using an exact staged payload from
`tools/edit_0869/package.py`. That packaging helper now reads the current CMake
version; its historical directory name does not select a product version.
`run.py` always launches year 2027 in a fresh owned `build/` profile. It never
installs into an artist profile. Match the staged script, native modules,
Gallery and independently versioned Analyzer before running a scenario.

| Fixture | Scenarios and purpose |
| --- | --- |
| `ui_checks.ms` | Density pick/Clear/Undo, procedural thumbnail reuse and invalidation, pending Manual preservation; native body geometry and teardown/reselection |
| `drag_checks.ms` | Immediate handle feedback for 100, 10,000 and 30,000 placements; actual Move axis during/after a physical drag; one final publication; Undo/Redo/Cancel/save/reopen; Manual isolation of deferred feedback |
| `preservation.ms` | Authored edits and radius history from an explicitly bound 0.86.9 scene; matching Analyzer output consumed by Scatter |
| Existing `edit_0869/edit_workflow.ms` | Focused stacked-transform, palette/Manual and guarded-failure regressions |

`drop_prepare` exposes a Checker swatch and leaves density empty. Physically
drag that swatch onto the native Map target, choose **Instance**, then run
`drop_verify`. Direct `.picked` calls exercise handlers but do not prove drag
and drop. Likewise, `setup` and `physical_begin` only arm the viewport observer;
perform a real gizmo drag before `physical_end` and `physical_verify`. The
observer records one stable selected ID, authored delta, actual handle matrix,
Max's `getTransformAxis`, publication epoch and preparation/build counters.

Run `layout_prepare`, verify a single column, physically widen the command
panel, verify again, run `layout_reselect`, then verify the fitted dialogs again.
Geometry checks compare content HWNDs against their native parent bodies; a
control fitting an undersized centered dialog is insufficient.

The shared harness records separate run/request/artifact identities, explicit
assertion manifests, loaded file hashes and terminal results. On timeout,
observe the original request; do not replay a mutation. Freeze final fixture
bytes alongside the delivery evidence. Earlier failed candidates retain their
own identities and must not be counted as final acceptance.

For requested Max 2024/2026 payloads, use `offline_build.py --build-only` and do
not launch those hosts or run their native executables. This flag suppresses
test execution; CMake can still compile test targets. Mark the payloads built
and untested. Only the current 2027 passes establish runtime qualification.
