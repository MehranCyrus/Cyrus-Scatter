# Complete capability-family comparison

6 October 2026. Covers **C01–C34** from the project's declared [native/MCP matrix](../Current_System_2026-10-05/CAPABILITY_MATRIX.md). Each row identifies implementation and the relevant review decision. It is not a statement that every combination of the 245 semantic controls has runtime coverage. Closest tyFlow analogues are conceptual unless marked binary-verified in [internals](TYFLOW_INTERNALS.md).

Most native scope has audited private Max 2027 evidence plus fresh offline tests; installed artist-session behavior still needs the appropriate gate. MCP's twelve tools/seven resources have their separate dated host receipts. Policy 3 is read-only; plans 1/2 remain closed, locally approved and bounded.

## Practical extension order

Preserve closed plan schemas 1/2. Qualify one typed policy-3 authoring slice over the current evaluator and transaction, then add explicit recipe/assets reconstruction and bounded render studies. A future learning loop needs real generation-linked images, asset completeness, artist accept/reject/tie/neither feedback, dataset eligibility and held-out evaluation. Engineering traces and tool-count growth alone do not teach composition. [Prior extension contract](../Current_System_2026-10-05/MCP_EXPANSION_SPEC.md).

The native system already supports much more than MCP can mutate. Improving documentation/capability discovery is useful today; widening remote authority simply to match the local UI is not a substitute for typed ownership, stale-state, rollback and bounded-work tests.
