# Maturity, evidence and practical limits

6 October 2026. Cyrus Scatter 0.72 is a substantial development candidate with real tested subsystems. It is not yet a broadly qualified commercial release. Neither file extension, line count, tool count nor one passing fixture supplies an overall maturity percentage.

## Evidence levels used here

| Level | Evidence needed |
| --- | --- |
| M0 | Requirement/design only. |
| M1 | Implemented source/build; behavior not yet independently exercised. |
| M2 | Relevant offline contract/correctness/failure tests. |
| M3 | Supported behavior exercised in a pinned private Max runtime campaign. |
| M4 | Intended hosts/renderers, artist workflows, resource failures and long mixed sessions qualified with useful measurements. |
| M5 | Publication/support readiness, delivery/recovery/commercial boundaries and maintained regression evidence. |

These levels are per **supported slice**, not certifications of a whole feature family. An M3 ordinary path may still have an M1 edge case. M4/M5 are goals, not claimed achievements.

## What is comparable to tyFlow

Selected tyFlow code verifies native Qt/parameter binding, selective validity, retained custom rendering, preparation-time buffer filling, instanced drawing and thread-pool job paths. Cyrus already has native numeric calculation, relevant-input reuse, retained Mesh/Point resources, stable ownership and bounded publication. These are the right kinds of mechanisms; they are not proof of equal implementation quality or throughput.

tyFlow is a broad particle/simulation product; Cyrus is currently an ordered procedural static-placement tool with specific authoring contracts. A simulation event/history cache, a free/pro CPU restriction or a reduced display mode can change a benchmark. Compare a matched static workload before drawing a speed ranking. [Protocol](EXPERIMENTS.md#next-hostperformance-matrix--not-executed-here).

No matched performance evidence establishes Cyrus is faster/slower than tyFlow overall. No private analysis recovered a complete tyFlow collision scheduler, cache graph, GPU kernel set or failure/publication protocol. The review consequently cannot use those unknowns to certify Cyrus or prescribe a copy.

## Performance and correctness must remain separate

The new spacing oracle supports the current kernel's result correctness within tested domains, while E1 demonstrates selectivity failure under radius extremes. Similarly, Brush reference agreement does not establish bounded history memory; unchanged GPU upload counts do not establish free drawing; settled idle counters do not establish every callback is absent.

Three measured CPU costs justify focused improvements. The largest return is likely to come from eliminating unnecessary algorithmic work and bounding preparations before adding more workers. Which cost dominates the artist's scene still requires phase measurements; the extreme offline fixtures do not diagnose their playback by themselves.

## Release decision

Continue development from 0.72 while preserving the tested foundation. Finish the next measured computation/reporting loops, then qualify the intended UI/host/renderer and long-session matrix. Keep 1.0 reserved for demonstrated publication readiness. A completed documentation pass is not a release.
