# Primary-source recheck and R&D use

Checked again on 7 October 2026. Existing tyFlow binary investigations and their evidence are kept under the dated R&D folders; no new inference from strings, addresses or decompilation is treated as a verified private engine contract.

- **Max events and Undo:** the local matching 2027 SDK `object.h` identifies TransformStart/HoldingFinish as sub-object lifecycle callbacks. Whole helper-node movement needs a different event. [Autodesk reference messages](https://help.autodesk.com/cloudhelp/2027/ENU/MAXDEV-CPP-API-REF/group___reference___messages.html) describe node `REFMSG_CHANGE/PART_TM` and distinguish time-evaluation `REFMSG_TM_CHANGE`. [NodeTransformMonitor](https://help.autodesk.com/cloudhelp/2025/ENU/MAXDEV-CPP-API-REF/class_i_node_transform_monitor.html) documents weak node monitoring and recursion protection. The matching local `hold.h` defines EndHold, restoration and nested transaction behavior. These contracts informed the reproduced container fix; they are not performance measurements.
- **Validity:** [Autodesk time and intervals](https://help.autodesk.com/cloudhelp/2026/ENU/MAXDEV-Developer/files/overview/overview_time_and_intervals.html) explains valid-at-time caching. Unrelated animation should not invalidate a static procedural recipe; relevant animated inputs remain explicitly separate. A static scene and a displayed cached mesh do not by themselves prove no host CPU work.
- **Houdini profiling:** [SideFX Performance Monitor](https://www.sidefx.com/docs/houdini/ref/panes/perfmon.html) separates cooking, drawing, events, memory and CPU/GPU work. Cyrus evidence likewise separates candidate preparation/publication, retained uploads, immediate Proxy drawing, presented playback and whole-process resources. The useful lesson is measurement boundaries and dependency discipline, not copying an unrelated node architecture.
- **tyFlow:** [the public SDK](https://docs.tyflow.com/tyflow_SDK/) exposes integrations. Its [particle interface](https://docs.tyflow.com/tyflow_SDK/tyParticleObjectExt/) documents cached update/query sequencing and resolving channel indices outside particle loops. These are useful explicit boundary contracts; they do not reveal all private UI refresh scheduling, allocation, collision or engine concurrency rules. The earlier R&D is useful for hypotheses about native retained controls/data, but Cyrus maturity is assessed from its own source and reproducible tests. A `.dlo` extension alone does not prove faster UI or correct invalidation.
- **GPU instancing:** [FStorm's instancing documentation](https://fstormrender.com/manual/instancing/) describes renderer instancing benefits. Cyrus's native retained Mesh path already reuses source geometry and admitted transforms. It does not imply GPU placement or that the 100k Proxy immediate-box path is retained.
- **Presented timing:** [PresentMon console metrics](https://github.com/GameTechDev/PresentMon/blob/main/README-ConsoleApplication.md) define QPC and available presentation/CPU/GPU metrics. Dominant-swap-chain samples and synchronous redraw medians are separate evidence. Missing DisplayLatency/DisplayedTime data is unavailable, not zero.
- **Material placeholders:** [Autodesk missing classes](https://help.autodesk.com/cloudhelp/2019/ENU/3DSMax-MAXScript/files/GUID-5DD1729A-7549-44CC-9385-A0EAC354C437.htm) explains preserved missing plugin objects and missing properties. The private copy of the supplied original already contains seven Missing_TextureMap instances before the generated garden is loaded. Resolving ordinary bitmaps/CProxy files does not prove all material classes are available. Do not replace their intended appearance from names alone.
- **Undo flushing:** [Autodesk manual and automatic garbage collection](https://help.autodesk.com/cloudhelp/2022/ENU/MAXScript-Help/files/MAXScript-Language-Reference/Variables-Assignment-and-Scope/Memory-Allocation-and-Garbage/GUID-CA7ABB4B-6CB6-47B7-903D-84D2F45D993D.html) documents full collection's Undo flush and light collection's preservation. [Callback inspection](https://help.autodesk.com/cloudhelp/2025/ENU/MAXScript-Help/files/MAXScript-Tools-and-Interaction/Change-Handlers-and-Callbacks/GUID-C1F6495F-5831-4FC8-A00C-667C5F2EAE36.html) provides explicit callback inventories. The first cold Redo failure is a reproduced missing-stack observation, **not proof that garbage collection caused it**. Do not introduce global heap tuning or remove Undo based on that hypothesis.

The next R&D should target the measured Proxy path, worst-case neighbor admission and projected movement. More abstraction or GPU compute needs a measured bottleneck, explicit copied-data/main-thread boundaries and acceptance cases before implementation.
