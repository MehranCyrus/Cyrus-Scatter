# Requirements to review against the implementation

These are the artist's intended workflows, consolidated for an independent review. “Implemented” below identifies a code path to inspect; it does not waive validation or require retaining that implementation if a simpler correct approach exists.

| Requirement | Intended behavior / implementation claim | Review focus and evidence |
| --- | --- | --- |
| Procedural top-to-bottom evaluation | Visible layer and paint-set order determines ordinary collision winners. Cached data can be reused without reseeding unaffected candidates. | Check actual evaluation ordering, stable owner/candidate IDs, allocation tie order and deterministic cold/warm results. No requirement to copy Houdini's entire node system. |
| Layer ownership | Each named layer exposes its complete settings. General scheduling, receivers and display settings remain global. | Verify native page owners and set-aware bindings. UI restructuring must not create duplicate independent settings or change calculation order. |
| Paint sets | A layer can contain red/blue/yellow flowers and grass, each with sources and editable coverage, sharing declared layer defaults. | Count/density is a shared layer budget allocated by enabled weights; it is not automatically a full budget per set. Check reordering, Base-set identity and lifecycle. |
| Three collision scopes | Self within one set, relationships between sets, and relationships between layers are separate. | Resolve each pair once. Explicit disabled overrides must override defaults. Ordinary later plants cannot displace earlier winners; protected authored-edit exceptions must be clear. |
| Adjustable radius | Source footprint, optional scale following, and per-instance overrides determine spacing. | `factor * (radiusA + radiusB) + gap`; equality allowed. XY/3D explicit. Conservative scale bound, mirrored/sheared transforms and clone identities. Radii do not resize meshes or perform triangle collision. |
| Two kinds of filling | Exclude authored foreground coverage or fill gaps between accepted plants; bounded replenishment is a separate choice. | Verify field complement exactly once; foreground enable/visibility/count semantics; earlier references; independent spacing and target controls. Never equate shortfall with a proof of fully packed space. |
| Procedural Brush | Editable paint/erase on flat and rounded static meshes; history survives Save/Undo. | Surface anchors, normals, strength/softness, topology guards, support versus transformed coordinates. Coverage samples must not be mistaken for accepted plant centres. |
| Area and transforms | Existing include/exclude, source assignment, density, diversity and randomization remain meaningful. | Read all policy adapters and fail/guard unsupported combinations. Test reset controls and source lift/scale relative to coverage and radius. |
| Authored edits | Moved/cloned plants and radius overrides preserve identity; deleted/ineligible plants do not leave stale blockers. | CS Edit binding, protected zero-quota plants, clone IDs, source/receiver replacement, failure/Undo, per-instance radius binding resets. |
| Cache correctness | Ordinary navigation/UI browsing does not regenerate placements. A failed update retains a coherent last good result. | Candidate/prepared keys, dirty propagation, solve replay cost, atomic publication, old/new resource lifetime, pending/error statistics, renderer/export consumers. |
| Manual and Live | Manual retains last completed output until Update; Live schedules/coalesces edits. | Auto-save is distinct from recompute. Latest spacing UI needs direct-input and Live tests. Look for timer reentrancy and lost changes. |
| Viewport performance | Preserve 0.64 retained Mesh and 0.63 retained points. Preview budgets must not alter exact output. | Compare same scene/output/budgets and disabled baseline. Check uploads/build counters and tail latency. Heavy Proxy is a known open issue; CUDA/OpenCL is not an implemented solution. |
| Viewport visibility | Hidden layers/sets disappear from preview, retaining final-output and collision participation. Disabled output owners stop participating. | Verify Base/child propagation, caching, background references and Bake/render/export distinctions. |
| Native Max UI | Minimal native controls, usable width, reliable expansion, scroll/drag and more columns when panel is wider. | Current highest-risk unfinished change. Whole layers currently flow as pages; inner sections stay together. Check whether that meets the artist's expectation, not just whether SDK calls compile. |
| Statistics | Clearly distinguish candidate quota, accepted plants, shown instances, point-cloud samples, shortfall, cache/pending/error. | Report last published generation consistently. No fake precision or stale counts presented as fresh results. |
| MCP integration | Existing supported plans and bounded approved transactions remain safe; actual layouts can be inspected. | Policy 3 currently read-only. Closed schemas 1/2 cannot overwrite it. Metre conversion, IDs, counts and epoch must agree with host output. No implication that all UI controls are remotely mutable. |
| Future ML | Separate artist-style companion may propose versioned recipes from references and approved examples. | Keep future work explicitly unimplemented. No invented LoRA training, learned model, automatic plan interpretation or data uploads. Inspect extension boundaries only. |
| Compatibility and release | 0.7 development, preserved class IDs, explicit policy conversion, matching per-SDK binaries. | Test save/reopen, old policies, duplicate-load prevention and installer pairing. Max 2026 host testing remains separate from SDK tests. Do not rename internal compatibility identifiers for cosmetic consistency. |
| Engineering simplicity | Preserve measured improvements with the fewest reliable mechanisms. | Identify duplicate ownership/state, unnecessary polling/remounting, broad catches, hardcoded limits/paths, memory peaks and speculative abstractions. Recommend bounded fixes with observable acceptance criteria. |
