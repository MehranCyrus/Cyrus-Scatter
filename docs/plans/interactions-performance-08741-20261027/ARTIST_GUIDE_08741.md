# Using Interactions in Cyrus Scatter 0.87.4.1

Use separate Scatter layers for objects that act as colliders and plants that react to them. Prepare each original plant source once; its scattered instances reuse that preparation while keeping their own position, rotation and supported uniform scale.

1. Add the stone, tree or other obstacle as a source in a layer. In **Interactions**, choose **Collider**. A closed stone or sphere can use **Original closed mesh**. For a tree, **Build trunk colliders** creates a lightweight approximation while the original tree remains visible. Review the proxy or assign your own closed mesh if its shape does not fit.
2. Add each grass, flower or other plant to a reacting layer. Choose **React to colliders**, select the original source in the list and press **Prepare model**. Use **Show source guides** to inspect the result and **Edit preparation** when automatic inference needs correction. Repeat preparation for each different original source; it is not repeated for every scattered instance.
3. Use **Cyrus Scatter Edit** to select and move an individual scattered collider. In Live mode the relevant contacts are recalculated; workload and model complexity determine how quickly the viewport responds. A successful contact result is a fitted static pose, not wind or a time-based physical simulation.

**Contact gap** is a nonnegative clearance around the collider. Increasing it can push nearby vegetation farther away and can also make more fixed roots count as covered. **Hide roots inside colliders** removes covered rooted groups from the interaction result; leaving it off instead reports a conflict if a collider contains a fixed root. Move the collider or change the gap if the fixed root must remain visible.

**Preview leaves / blades (%)** controls the lightweight interaction preview, not how many stems are prepared. Lower values can make a dense viewport easier to navigate; use a higher value when judging shape. The panel warns when a checked guide shows excessive shape change. **Check full visible mesh** checks the complete visible triangles for penetration and excessive edge change; the absence of the early warning does not mean that every triangle has passed. This diagnostic can be expensive on large assets and does not replace visual review or a renderer test.

In **Viewport & render**, the **Idle triangles** and **Navigating triangles** limits reduce the Mesh preview workload. Lower limits may omit detailed instances or replace them with boxes; they do not generate a lower-polygon copy of each model. The large-scene sample in the delivery report did not show a consistent speedup from lowering them, so adjust them while judging both appearance and responsiveness in your own scene.

**Minimum stem** and **Branch connection** affect preparation; changing them rebuilds the prepared result. **Refinement stiffness** affects the iterative fallback solver; many contacts use a faster hinge and will look the same at different stiffness values. The **Preparation limits** controls are for models that exceed a stated source, guide, memory or work budget; increasing a budget does not repair incorrect topology. If a model reports unresolved guides or unattached pieces, inspect it in **Edit preparation** rather than repeatedly raising limits.

The current solver requires positive uniform instance scales and closed collider meshes. Mirrored, sheared or nonuniformly scaled interaction instances need a different setup. Automatic trunk proxies do not cover every exposed tree root or canopy branch. Tea Tree - 03 is a known preparation case requiring further guide/attachment repair; Common Blue Violet - 05, Lavender - 01 and one tested Arthropodium - 04 contact need deformation review. Large, dense contacts can take over a second to update on the measured machine, so live dragging is not guaranteed to be fluid. See the [delivery report](DELIVERY_08741.md) for the measured tests, installation identity and remaining limitations.
