# Interaction campaign — working investigation

This is the campaign's chronological investigation, not a universal performance claim. The user selected the four-part version **0.87.4.1** for a Max 2027 performance and reliability follow-up. Current saved schema 62 and independently versioned products remain unchanged. Earlier candidate observations and open checks below retain their historical context; the [delivery report](DELIVERY_08741.md) records the final scoped results and remaining work.

## Confirmed baseline observations

- The owned 0.87.4 Max 2027 sweep attempted **33 distinct sources** from copied, hashed scenes and the model library, with 100% foliage preview, fixed roots, no root hiding, zero contact gap and three sphere contact directions. Of those, **31** completed contact tests and **26** passed all three full visible-mesh audits and move-away restoration. Individual receipts and the model-level table are retained in [baseline evidence](evidence-0874-baseline/model-summary.csv); the [JSON summary](evidence-0874-baseline/model-summary.json) preserves exact source/settings identities and failures.
- Five models had at least one full-mesh quality result above the existing 25% maximum stem-edge-change check despite zero reported penetration and planted root anchors. These cases require examination of absolute as well as relative edge displacement and exact binding; the threshold has not been relaxed.
- Initial synchronous measurements show some dense sources spending much longer in viewport synchronization than in the contact solver. A host-thread stage profiler will identify which existing sync work dominates. These measurements are not presented frames per second.
- Myrtle - 03 reached the configured 256-million preparation-work budget and Tea Tree - 03 reached the configured 8,192-guide budget. Both baseline failures are preserved; higher-limit functional retries are described below.
- Current `shared-library.ms` compared the Gallery assembly's four-part .NET version with `0.87.4`, while its build and the Library UI require `0.87.4.0`. The candidate's version bump makes both comparisons use `0.87.4.1`; actual Library opening and the shared store still need a Max host check.

The first heavy-fern profile found a **1,235.5 ms** `refreshPreview` stage and **176.3 ms** retained-publish/status stage after one collider edit; subsequent unchanged sync calls took **10.9–12.6 ms**. A separate warm source capture of that same 593,787-triangle model and its 18,686,248-byte saved definition took **804–854 ms** per call in this owned process. Diagnostic counters also showed a complete scatter epoch/build increment on the collider edit, so eliminating source parsing alone will not establish changed-only scatter behavior. These are synchronous measurements from an instrumented copy of the 0.87.4 script, not pointer latency or displayed frames.

Candidate change under test: reuse a previously validated immutable source when the exact saved-definition SHA-256, source watch and validity interval, units, rig, settings and collider mode still match. The cache remains weak and source-owned; invalidation and initial parse/admission are unchanged. No new persistent data, Undo entry or peak geometry buffer is introduced. Changed or invalid definitions and stale source geometry must still fail before a successor publishes. Unusual non-plant native calls retain their prior validation. Re-measure the same heavy source and exercise tampered definitions, source changes, undo, save/reopen and failure retention before accepting the change.

The first candidate's same-source warm median was **108.4 ms** versus the recorded **843.5 ms** baseline; its three heavy-fern contact/audit cases still passed. The median measured move/ensure/sync/redraw command fell from **1,619 ms** to **902 ms** for the same three positions. The baseline host had already run many cases while the candidate host was newer, so process age and memory are confounders; repeat in comparable hosts and do not interpret these timings as FPS. The candidate rejected modified acceptance/fingerprint, changed settings and changed watched geometry while retaining its previous complete publication. The Layers > Recipes button and private shared store opened with matching `0.87.4.1` assembly identity and no notice; that isolated store contained zero models, so library-content browsing is not yet established by this check.

The three captured geometry regressions reproduced in the independent numeric kernel with the same reported strain as the Max host. The worst fern edge is about **143 mm** long and changes by **40 mm**; it connects an anchored root vertex to a vertex bound in guide span 2. This is a material shape defect, not merely a high percentage on an insignificant edge. In the violet and lemon-balm cases the worst edges connect the fixed root to first-span vertices, changing by about **0.62 mm** and **0.19 mm** respectively. Candidate skinning/root-span changes must be checked against the same full-mesh collision and root constraints; the differences in topology mean one assumed fix may not resolve every model.

An experimental successor derives a bounded preferred hinge pivot from edges adjacent to a planted root and keeps the rooted skin/attachment frame continuous at the base. It can fall back to the former shorter hinge if the preferred pivot cannot clear an obstacle. The pivot array is per immutable prepared source, not per instance; preparation scans existing triangles once and includes the array in source payload accounting. The existing tangent and exact-mesh checks remain required. This is a hypothesis under test, not yet an accepted fix; the three captured regressions and other known-good models must be replayed before a delivery.

On the three captured kernel fixtures, the prototype reduced maximum relative stem-edge changes from **27.88% to 19.59%**, **30.97% to 23.34%**, and **34.28% to 17.37%**, respectively, with zero reported penetrating vertices/triangle crossings and no root-anchor movement. These are numerical replays, not yet the final Max or render qualification; the new worst fern edge is longer and changes by about 52 mm in absolute terms, so a passing percentage does not by itself establish the desired visual quality.

The higher-limit functional retry admitted Myrtle - 03 with 2,048 million work units and passed the three contact/audit checks. Tea Tree - 03 still returned a preparation review failure with a 32,768-guide and 2,048-million-work allowance: the retained report lists 23 unresolved guides and 10,238 unattached parts. The numbers do not establish that increasing limits further would solve its topology. Initial retry attempts on the overused baseline host failed at fixture import; those are test-harness failures and are not counted as source or plugin failures. The successful higher-limit runs used a clean candidate host and ran while a separate numerical build was active, so their timings are not comparable performance measurements.

An initial test combined source picking and a deliberately failed Prepare inside one private transport callback and saw the newly added source rolled back. Repeating the same actions in separate Max message ticks retained the source identity, the prior definition hashes and the scatter epoch; the first result is retained as a fixture limitation, not a confirmed interactive defect. The candidate improves the generic preparation failure message by showing unresolved-guide and unattached-piece counts and pointing to **Edit preparation**; it does not automatically repair this tree.

The collider-count kernel isolation uses 200 nearby plant bounds sharing one real source, one moving collider above the geometry, and deliberately distant extra colliders. With identical plant/contact inputs and five runs per tier, the median fit stage grew from **0.30 ms** at one collider to **17.10 ms** at 4,096, even though the extra colliders were irrelevant. These densely overlapping bounds are a stress fixture, not an art-directed scene or Max-frame measurement. An obstacle-bounds index is being considered: it must retain sorted, exact candidates; include edited colliders at their latest transforms; discard their obsolete original bounds; respect deletion/Undo; and leave prior complete snapshots intact on failure. Base and transient index/scratch payloads must remain bounded and separately reported.

The current indexed prototype returned the same 200 affected plants and reduced the median 4,096-collider fit stage to **0.34 ms** in that fixture; the one-collider fit was **0.32 ms** versus the baseline **0.30 ms**. Its total retained index payload at that tier was about **0.90 MiB**, with a separately charged worst-case query scratch bound of about **0.41 MiB** and a roughly **192-byte** moved-obstacle index for this particular step. Those are explicit payload/bound figures, not process or GPU peaks. Numeric tests cover an obstacle moving in from outside its old index bounds, another moving away, disable/re-enable, independent full-mesh audit, and atomic rejection of more than 64 relevant colliders. Final large-scene, host, physical-pointer and version-matched package qualification remain open.

The candidate raises the **global** collider admission from 4,096 to **16,384**, with an early explicit rejection at the bound. In the analogous numerical stress fixture, the baseline rejected 16,384; the candidate admitted it and returned 200 affected, separated plants with a median **0.30 ms** fit stage in three runs. The sampled base obstacle-index payload was about **3.10 MiB** and the conservative query-scratch bound about **1.53 MiB**. The distinct existing limits of **64 relevant colliders per plant** and **4,096 transient edited instances** remain. These kernel results do not establish interactive performance at that scale in Max.

An audit of the existing **Refinement stiffness** control found that its extremes produced identical pose digests in all eight captured contact fixtures tested; each used the fast hinge path with zero iterative solver iterations. Source inspection shows the value adjusts the iterative solver weights, while a successful bounded hinge does not consult it. It therefore must not be described as a general stiffness or wind control. The existing control is retained for compatibility, and its limited applicability should be explained rather than promising visible changes in every case.

## Measurement discipline

Baseline and successor inputs must use the same model hash, source settings, plant and collider transforms, quality, unit system and movement path. Per-model synchronous timing, solver time, resource sampling, exact full-mesh audits, and actual pointer/display observations have distinct meanings. Save failures and preserve the last complete publication; do not claim a practical speedup from a different foliage fraction or from an empty contact query.
