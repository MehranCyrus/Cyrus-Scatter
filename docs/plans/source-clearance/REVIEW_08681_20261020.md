## Spacing correctness

### Original P1: displaced previous-round blocker — corrected

Relevant source: [same-prefix settlement](../../../AminScatter/src/source_clearance.cpp#L214), particularly the stale-blocker scan at line 269; [current evaluate route](../../../AminScatter/src/procedural.cpp#L98).

The original independent `review_probe.cpp` was copied into the fresh review directory and rebuilt against the current `procedural.cpp` and `source_clearance.cpp`, using the qualified supporting libraries. Its geometry and assertions were preserved.

The ordinary layer has candidates at X=0 and X=1.5, radius 1. A preferred layer initially tries X=100, which a protected edit blocks, then refills at X=-1.5. The refill displaces the ordinary X=0 candidate. The X=1.5 candidate is now three units from the winner and must survive the two-unit clearance requirement.

Both the two-round and sixteen-round runs now return ordinary survivor index 1, preferred survivor index 1 and the protected edit. They settle in two outer rounds without an obsolete limit warning. The dependent ordinary layer does not need extra refill allowance merely to reconsider its already authorized candidate. See `probe-run.log`.

The correction disables stale previous-round rejection hints and repeats admission/conflict settlement within the same prefix. It does not spend another layer's refill round to repair an invalid hint. This addresses the original defect directly.

### Original P1: unused source changes cleanup scheduling — corrected

Relevant source: [participating-source selection](../../../AminScatter/src/source_clearance.cpp#L75) and [component compilation](../../../AminScatter/src/source_clearance.cpp#L146).

The original cleanup reproduction was rerun unchanged. A candidate in the first layer is removed by cleanup; the later layer should then keep its candidate. Changing only an unused source's preference now preserves that later survivor and the original ordered schedule.

Participation considers protected edits regardless of ordinal and the full authorized refill pool where refill can run. Cached samples outside the permitted prefix/attempt limit do not activate a dormant source. Authored metadata is still validated: an inactive row does not exempt invalid settings from validation. The delivered native tests exercise protected-only sources, eligible suffixes and unauthorized cached suffixes; fresh host tests also exercise a zero-weight source.

### Additional independent probes

`chain_probe.cpp` was written specifically for this review. It checks 1,200 randomized seven-layer scenes against a separate exhaustive final-pool oracle, with:

- Four ordinary layers containing three source policies each, two preferred refill populations and protected blockers.
- Candidate-ordered ordinary acceptance, two and sixteen refill rounds, variable radii, and mixed XY/3D distance requests.
- Cross-layer blocker chains and two preferred populations that can also conflict with one another.
- A metamorphic comparison adding large-radius preferred sources whose cached rows remain unauthorized.

All 16,800 layer comparisons passed. This extends the delivered 500 refill-oracle cases beyond one ordinary layer and one preferred refill population. It is not an exhaustive oracle for every cleanup/Count/paint combination.

The original ten-empty-layer probe with 512 source records per layer changed from approximately 199 ms in the earlier review to **1.7131 ms** in this run. This measures metadata/evaluation overhead for an empty plan, not Max placement performance. Source inspection confirms one compiled context per solve and at most two witnesses per exact equivalent policy cohort; differing metrics, requests, targets and preference remain represented.

### Hierarchy and priority assessment

The implementation retains the intended division: layers own populations and their defaults; source rows own radius and individual clearance policies. Native conflict resolution uses protected edits first, preferred admitted sources next, then layer/set/candidate order. Count admission happens before conflict preference. Preference therefore does not allocate a later model an additional Count slot.

The delivered Count-admission, independent-inheritance, equivalent Defaults/Custom, cleanup, deterministic replay and bounded-work tests passed in each SDK suite. Host integration also passed independent multi-selection edits, equivalent-rule output fingerprints, later preferred-layer clearance, source replacement and Point/model conversion without losing the clearance identity.

Distance remains a radius-based center test, using the relevant pair constraints and XY or 3D metric. It is not exact mesh intersection or a guarantee that every irregular leaf boundary stays a specified distance from another mesh.

The new settlement-row ceiling is separate from neighbor visits. Hard budget failure rejects the successor; normal underfill/round exhaustion is reported in the result. The limit/error and satisfied-dependent warning regressions passed. I did not force the new 50-million-row ceiling through Max or exhaust system memory.

The cache no longer keys reusable appearance solely by the placement snapshot address. It checks dependency revisions and exact source-triangle correspondence, while weak geometry references allow retired snapshots to be reclaimed. Mesh items retain compatible geometry buffers, UVs, textures and immutable material handles while changing instance streams. The appearance mode and opacity responsibilities are separated appropriately: colored Mesh uses the supported opacity cutout with identification colors; Textured Mesh also samples material color. Opaque colored Mesh returns without an atlas or UV stream. A full textured preparation can satisfy a later colored display; a cutout-only preparation cannot incorrectly satisfy a textured request.

## Independent performance comparison

The baseline host loaded bytes matching the 0.86.8 MZP. The final host loaded the exact installed 0.86.8.1 pair through private profile copies. Both reopened the same frozen A006/A007 Count-200 scene and ran five warm radius edits per display mode. The final recorded comparison ran sequentially, with the other test host idle. The artist's pre-existing Max session remained open.

All **20 complete placement/radius publication fingerprints** match between baseline and final, in addition to the accepted counts `[138, 134, 132, 130, 126]` for every mode.

| Textured Mesh median | 0.86.8 | 0.86.8.1 |
| --- | ---: | ---: |
| Radius setter | 0.559 ms | 0.558 ms |
| Solve and preview preparation | 787.850 ms | 100.606 ms |
| Nested redraw portion | 75.336 ms | 80.103 ms |
| Combined operation | **863.703 ms** | **181.132 ms** |

The combined improvement is approximately **4.77 times**, or **79.0% less elapsed time**. This independently supports the reported approximately 921-to-187-ms improvement without promising identical timings on a busy workstation. Earlier review runs varied: final Textured medians were about 218 ms under concurrent qualification and 148 ms in another warm run. Those logs were retained separately.

For transparency, the last matched run's combined medians for Point/Proxy/colored Mesh were respectively 149/151/139 ms in baseline and 171/176/175 ms in final. These modes did not improve in that run. The small number of trials and observed workstation variability do not establish the cause or a reproducible regression; a controlled repeated comparison would be needed before attributing those differences to this patch.

All timings above are **warm diagnostic wall-clock operations**. Cold startup, import and first material realization are not included. The nested redraw loop runs with publication/presentation suppression in this fixture, so its zero transform-upload deltas are not evidence that a complete GPU frame was presented or that no upload was needed. GPU reuse conclusions instead come from the separate frame-separated checks and presented-owner stress run. Baseline map-counter zeros mean unavailable instrumentation. No FPS, frame-latency, renderer-throughput or general cold-performance claim is made.
