# Max 2027 scene preparation tool

Independent private **0.1.0**. The entry point is `presentation-studio/tools/max2027/prepare_scene.py`; the original experimental building workers remain historical evidence. The complete pipeline passes an owned fixture, prepared-Max reopening and two byte-identical heavy-building reproductions. See the [building study](BUILDING_STUDY.md) for exact sources, artifacts, runtime qualification and limits. This is not a native Scatter feature or installer.

## Contract

The entry point accepts an original `.max`, a fresh output directory and a closed JSON recipe. It creates its own Max 2027 profile/process, copies the source, records source/recipe/tool identities and modifies only that derivative. It never attaches to an existing artist host, overwrites the source, installs plugins, changes a normal profile, or updates existing output. Failure leaves diagnostics and staging files without publishing a final GLB. A new run must use a fresh destination.

Static export uses one explicit bake frame. Geometry operations use evaluated triangle counts, not `getPolygonCount` estimates. Native host APIs and publication stay on the Max thread. Process each shared object stack once; the most conservative layer rule wins across its placements. Freeze each accepted ProOptimizer result immediately, reconnect the original instances, and verify each placement's handle, name, layer, material and world transform. A missing evaluated mesh is diagnosed and retained; missing proxy geometry cannot be recovered by the tool. Invalid or increasing reductions fail the run.

Defaults preserve geometry and source appearance. Reduction percentages, removal of UV/normal data, normal reconstruction, unsupported-material approximation and recentering require explicit recipe fields. Approximation is labelled and audited; it is not renderer equivalence. Material assignments are cached by original identity and preserve MultiMaterial IDs. Texture substitutions identify exact files and their hashes. No AI service or external download occurs during preparation.

Native GLB output and an export-node sidecar remain in staging. The sidecar records source handle/name/layer/parent, instance owner and canonical object transform. Bind native reused instance names by shared owner plus world transform; reject ambiguous correspondences. The public preparation output organizes static placements into named identity-transform layer groups while retaining distinct source-qualified entity IDs. IDs include the source SHA namespace and original handle; identical-source repeats retain them, while a changed source namespace requires explicit replacement review. Studio layer UUIDs remain independently owned and can be preserved through reviewed group assignments. Preserve original hierarchy in the prepared Max scene and diagnostics. Do not claim a merged source primitive can be separated downstream.

Post-export operations preserve placements and layer membership. Deduplicate resources, weld, prune unused data, prepare embedded textures and quantize with recorded settings. Optional error-limited simplification is scoped to explicit layer rules; shared meshes use the most conservative rule. Protected and unmatched layers receive no simplification. The optional crease-normal rebuild uses the proven 45-degree support-layer operation. Finally apply the qualified lossless Meshopt codec and validate the complete result with the app's numeric/resource admission before publishing it.

Canonical glTF coordinates are metres and Y-up. A recipe's explicit Max translation is recorded together with its canonical equivalent. The building recipe uses `[4000,1700,1900]` source centimetres, i.e. `[40,19,-17]` metres Y-up. Recentring adds one static identity parent, retains the source controllers/hierarchy below it, and checks controller key counts plus sampled world poses. The original building's animated Corona camera/target pass 402 poses with 0.00273 mm maximum position error and 0.000007267 basis error. Author/export the final supported native camera from the resulting prepared scene; do not apply a second transform in the app. The conservative default is zero translation.

MultiMaterial iteration uses `materialList.count` and slot-array access, then copies material IDs, names and enabled flags. `numsubs` is not a slot count when IDs are nonconsecutive; the [Max 2027 reference](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Material-MAXWrapper/Material-Types/GUID-7ECB1E85-6199-4143-BEDA-3B26DD35E0C3.html) explains the distinction. A native source/prepared comparison reproduced the defect in the initial adapter and led to the correction. The earlier experimental adapter shares that defect and is not a qualified source of nonconsecutive-ID preservation.

The native exporter also ignores nonconsecutive face/slot IDs in the tested two-colour fixture. `export-materials.ms` creates temporary compact-ID copies only for affected export placements. It shares geometry when ownership and mappings agree, retains material assignments and object transforms, and rejects unmapped face IDs. Cleanup removes copies before saving the prepared Max, preserving its source IDs and hierarchy. The exported GLB must contain both colours, and the saved Max must reopen with original `[3,7]` IDs. Both gates pass for fixture v6. The building's 41 MultiMaterials are already consecutive; its v4 reproduction creates zero export clones.

Compression identity is checked against the serialized uncompressed GLB. glTF Transform's writer can omit a near-default transform: the building probe changes one scale entry by 0.000000153, while all attributes, triangles and materials remain exact. The tool measures and bounds that ordinary serialization change separately; the Meshopt comparison still requires exact decoded geometry/materials/world matrices, allowing winding-preserving cyclic triangle-corner rotation only.

## Output and acceptance

Publish a self-contained optimized GLB, a prepared Max derivative, portable texture assets, the effective recipe and a report with original/native/final hashes, geometry/material/instance/layer counts, timings, resource estimates, missing dependencies and explicit appearance changes. Retain the native GLB and audit as useful comparison artifacts.

Offline tests must cover configuration validation, source/output guards, reproducible request generation and failure retention. Owned Max fixtures must cover shared owners, different per-instance materials, UVs, transformed instances, protected layers, missing/empty meshes and invalid operations. Roundtrip the resulting GLB through the actual app. Then reproduce the building workflow with a fresh run and compare its visuals, coordinates and source preservation. Source inspection, a green fixture, or an earlier experimental export alone does not qualify the complete tool.
