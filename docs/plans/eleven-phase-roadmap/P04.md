# P04 — density mapping controls

Implementation and scoped qualification passed after verified P03 commit
`a509e2e08d1e01f8b624872026d17fc5532eee84`. Git checkpoint is pending below;
this is development evidence, not release certification.

## Version and contracts

Select **0.84.0**, a minor version for a coherent new artist capability: choosing
receiver UV channels and sampled density resolution. Independent products remain
unchanged. Saved schema 58 gains neutral fields (channel 1, resolution 128).
Density bridge capability 1 requires the matching script/native pair; keyed
generation options now explicitly include the channel. F01–F11 remain applicable.

- Positive texture channels **1..99**, confirmed by Max 2026 SDK `mesh.h`
  (`MAX_MESHMAPS=100`; channel 0 is vertex color). Resolution choices are
  **64, 128, 256, 512**, stored as the actual dimension.
- Keep the current bitmap luminance expression, clamp UVs to [0,1], flip V for
  bitmap rows, and retain bilinear candidate eligibility. Existing Relax's
  nearest-pixel nonzero mask check remains unchanged. This phase does not change
  renderMap color management or introduce wrapping/UDIM evaluation.
- Copy the selected evaluated UV channel on the host thread. Reject missing,
  incomplete, out-of-range or nonfinite referenced UV data with the receiver and
  channel named. Previous complete publication remains available after failure.
- One transient bake cache per layer, independent of receiver geometry/UV keys.
  Reuse requires the same map identity, observed parameter revision, resolution
  and a containing map-only validity interval. Cache raw luminance and lazily
  derived inversion, at most two 512-square arrays per layer. Do not retain
  historical maps/resolutions or introduce a global cache holding scene assets.
  Cross-layer sharing is deliberately deferred; this avoids global ownership and
  invalidation complexity without losing reuse within a layer.
- Bake replacement is atomic after successful sampling/bitmap close. Reuse does
  not occur after map edits, Undo notifications or expired map validity. Map-only
  validity prevents static maps rebaking for receiver animation. Passive reads
  never request a bake. Cache counters describe preparation, not publication.
- UVs participate in the existing receiver geometry key only in Texture Density.
  Channel and resolution participate in candidate keys only in that mode. A
  resolution change is an eligibility change; it does not independently reset
  Edit identity bindings. Changed selected UV data follows the existing binding
  policy. Map eligibility runs before Edit: masked base candidates become dormant;
  their stored edits reappear when those candidates return. They do not bypass
  Texture Density. New UI callbacks capture the owner before control rebuilding.

## Required acceptance

Both supported Max versions: deliberately different channels, matching default
results, all resolutions/tiny features, invalid and partial UVs, invalid options,
map deletion/replacement/in-place and nested edits, map animation and static-map
reuse during receiver animation, Manual/Live, actual callbacks/Undo/owner changes,
copy/save/reopen/merge, units, Paint/Bands/filters/Relax and atomic failure.
Record cold/warm bake costs, bounded retained samples and relevant counters.
Run generated checks, native/Python suites and prior phase host regressions.
Physical/DPI coverage and untested renderer behavior remain explicit limits.
