The static adapter has not become a general Max scene/material serializer. Ready terrain preserves evaluated geometry and numeric map channels, including modifier output; it does not preserve an editable modifier stack. Captured references exclude unrelated objects with duplicate names.

Only the verified included receiver path can restore Paint with explicit saved/current unit conversion. Existing-terrain Paint substitution keeps its strict compatibility checks. No arbitrary-terrain reprojection or density-mask disabling is hidden in the loader.

One authored import hold owns assets/layers and a bounded publication restore record. Undo removes that import and restores the preceding complete publication; Redo retains scene-owned data and works without the original library folder. Failed staging cancels the hold and keeps the old result. A subsequent Update failure is separately reported because the authored Add already committed.

The final timing correction handles delayed node notifications before the explicit Update. The existing callback uses a 150 ms batch delay, consistent with Autodesk's [Node Event System](https://help.autodesk.com/cloudhelp/2026/ENU/MAXScript-Help/files/MAXScript-Tools-and-Interaction/Change-Handlers-and-Callbacks/GUID-7C91D285-5683-4606-9F7C-B8D3A7CA508B.html). The ready command holds automatic display scheduling for a bounded 300 ms settling stage, then calculates and releases it on success, failure or close. It never clears host notifications. A reproduced predecessor went from current to pending with unchanged settings; the correction keeps it current and performs one Live solve.
