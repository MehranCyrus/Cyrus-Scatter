# Portable recipe package — supported adapters

Retained 0.86.1 behavior: [selected-surface contract and qualification](DELIVERY_0861.md). Direct Load binds the captured terrain, creates a setup only when needed, adds layers, validates channels/Paint before mutation and maps static paths through the saved receiver frame. Authoring host provenance admits 2024, 2026 and 2027; data-only packages can be read across these hosts. This does not make a newer `.max` scene readable by an older Max. No mask/Paint is disabled and no included receiver is substituted.

Historical 0.85.3 extension: [ready-preset contract and qualification](LOAD_0853.md). Graph 2 adds bounded static Bezier spline context (128 curves, 4096 total knots) and packaged evaluated receiver geometry/maps. Ready Save uses captured exact references; all eight examples become asset-backed. Ordinary packages/graph 1 retain their existing adapter. Ready Load adds layers and explicitly Updates once, with publication Undo/Redo and current-or-included terrain selection. Only transaction-created verified receivers may use packaged Paint unit conversion; arbitrary receiver substitution remains strict. Native file operations preserve containment/integrity checks through Windows long-path handling.

The remaining text records the preceding PG06/PG07 implementation contract, 0.85.1 candidate. It remains historical scope where the extension differs. This is separate from the MZP/EXE installer. See [progress](PROGRESS_0851.md) for qualified pairs and remaining work. The static mesh/Standard-material import command is implemented and has scoped owned-host witnesses; full delivery gates remain open.

An export creates a new immutable folder containing `cyrus.package.json`, the exact reviewed `entry.csrecipe.json`, `assets.json`, referenced Paint/thumbnail payloads and content-addressed asset files. Recipe identity, revision, settings and complete Paint bytes remain intact. Every role is either supplied by a packaged asset or explicitly external. Terrain, Paint receivers, paths, Analyzers and external spacing partners stay external in the initial adapter. Same-name assets are not automatically interchangeable.

The package manifest is version 1, with authoring host year 2024, 2026 or 2027, with closed fields for recipe/graph file descriptors and the exporter's redistribution declaration. Each descriptor has relative file, SHA-256 and exact byte length. The graph has closed typed node, mesh, material, map, file and external-role tables. File source paths remain outside the portable data. Each node keeps its own role bindings; shared material identity is retained within the graph. Current capture deduplicates repeated references to the same source node and material. Separate instances are captured separately; the writer deduplicates byte-identical payload files.

Initial bounds: 128 records per object table, 256 files, 32 MiB per asset file, 2 MiB graph JSON and 256 MiB for the complete package including Paint. Geometry uses a little-endian `CYRUSM01` typed payload: finite source-node-local vertices in metres, triangle indices, smoothing groups, material IDs, edge visibility and populated mapping channels. Object offsets are baked into the captured vertices; the source's node transform remains separate, including its pivot frame. Bounds are 100,000 vertices/faces, eight mapping channels in -2..99 and 300,000 vertices per mapping channel, subject to the byte limit. Decoding validates counts before allocating and rejects bad indices, repeated channels, truncation, non-finite coordinates and trailing bytes. Explicit normals currently reject instead of being discarded.

Source capture initially admits supported static standalone Box, Sphere, Cylinder, Cone, Pyramid, GeoSphere, Editable Mesh and Editable Poly objects without modifiers/groups/hierarchy. Supported static transform controllers and parameter blocks are checked. The explicit action freezes evaluated geometry into a mesh; it does not promise retention of a primitive's parametric stack. Unsupported controllers, plugins and scene dependencies need their own adapter. Further deformation/animation rejection tests are still required.

The current material adapter is Standard/Blinn with supported colours, opacity, two-sided flag, specular level/glossiness/soften, self-illumination and colour-lock settings. Ambient/diffuse/opacity map slots preserve their map identity, amount and enable state, including dormant slots. Direct recipe texture roles can share those same maps. Non-default properties outside this closed adapter reject. There is no arbitrary material/proxy/renderer conversion.

Bitmap scope is static noninterlaced RGB/RGBA PNG, 8 or 16 bits/channel, at most 4096 pixels per side and 16 Mpixels in aggregate across map instances (shared texture objects count once). A file remains within the 32-MiB cap. Header/chunk/CRC admission is not a substitute for Max's image decoder. Unsupported image formats, animated images, real-world coordinates, unsupported UV axes/noise/crop/output curves and colour pipelines reject. The supported UV channel, offsets, tiling, W rotation, mirror/tile/blur flags, sampler flags and scalar output settings are explicit. Derived UVTransform cache is not authored data: an un-evaluated detached UVGen can report identity after its parameters change. Output curves must match a fresh default, including when disabled.

The initial bitmap adapter requires normal default OCIO with the same configuration hash, rendering/data spaces and a resolved explicit input colour space. It rejects OCIO configurations with external FileTransform dependencies; Gamma/custom/environment configurations need separate adapters. It never changes scene colour settings. Capture compares every decoded linear pixel against an independently copied/opened file to reject unsaved in-memory differences. Max documents that a requested space can fall back, so actual status/name are checked ([Bitmap values](https://help.autodesk.com/cloudhelp/2026/ENU/MAXScript-Help/files/MAXScript-Language-Reference/Values/Bitmap-Values/GUID-9F6ABEE1-0728-4B39-8903-D909634C1304.html), [ColorPipelineMgr](https://help.autodesk.com/cloudhelp/2027/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Interfaces/Core-Interfaces/Core-Interfaces-Documentation/C-D/6BCD1EAA-1F16-4758-A07B-C2E31F94BEB2.html)).

The host captures geometry once on its thread, using native buffers rather than per-vertex MAXScript arrays. Only detached graph data and paths enter the file worker. The worker copies/hashes bounded chunks, verifies readback and typed mesh data, then renames an owned sibling directory into a new destination on local NTFS. Existing destinations reject. Cancellation before publication removes only owned staging; a cancellation arriving after publication does not undo a successful export. Input files, original recipe and artist objects are retained. Temporary captured meshes live in an owned profile staging folder; a host timer cleans them after the worker terminates and stops when no jobs remain. No background filesystem scan or capture runs while idle.

Native tests establish bounded codec and file-transaction behavior. The owned Max 2027 painted-border witness establishes actual export-dialog callbacks, exact settings/Paint preservation, source/material payload verification, no scene object changes or placement rebuild, stopped progress/cleanup timers and retained preceding Undo/Redo for its recorded pair. Scoped import/reopen/Scanline render and bitmap-value witnesses are recorded below. Large/cancel/unsupported matrices and final UI/soak qualification remain open. An export pass alone does not establish PG07 or final installer completion.

The default import creates independent hidden source meshes, shared materials within that package and new recipe owners in one authored hold. External terrain/path/spacing roles remain explicit; supported bitmap roles are packaged. Same-name scene assets are preserved; their names do not authorize reuse or replacement. A captured review binds the controller, relevant input key and package content. Failure after asset staging cancels the hold, retaining the preceding complete publication. Manual success waits for Update. Owned tests establish Undo/Redo without source files and scene reopening for the recorded supported pair. Existing-layer source replacement, arbitrary external bitmap graphs, XRef adapters and broader B26 coverage remain separate gates.

PG09's implemented reuse choice is **Reuse chosen scene models and keep their materials**. It exposes every recipe role for explicit binding, and makes no source/material import or ownership transfer. The selected scene models may intentionally differ from packaged models: this is a reviewed substitution, not a claim that their contents match the package. Review captures their complete supported graph using the same closed static adapter; commit recaptures and compares that graph, including mesh/file hashes, transforms, material/map values and shared relationships. Changed content rejects before authored import. These bounded captures happen only on Review/Load, never selection or idle. Names can supply suggestions but never authorize a commit on their own.

Borrowed model/map references use Max's ordinary scene reference graph. Cyrus does not delete those objects when removing imported layers or one setup, and does not keep a global package-ownership registry that could outlive the scene. Two setups and non-Cyrus users can share the same source/material. Native source dependency handling continues to control later geometry/radius/placement invalidation; a material-only edit is not an instruction to reseed placements. Scoped tests cover actual Load, Add/New, unchanged Manual publication, Undo/Redo without package access, changed material after review, deleting one setup, external material users and save/reopen. XRefs, nested populations and a renderer material-variant browser remain **unsupported**, not inferred from this reference-reuse slice. PG09 is therefore only partially implemented.

The file worker prepares detached Paint and mesh data before the authored transaction; the final Load repeats preparation and compares reviewed content. Its 256-MiB native payload accounting covers expanded Paint text and decoded mesh capacities, not total process/MAXScript/Undo memory. B26 remains a separate gate. Bitmap files are verified and atomically copied to `getDir #userScripts / CyrusScatter / ImportedAssets / <SHA256>.png`; an existing differing file is preserved and rejects. This immutable disk store intentionally survives scene Undo, package removal and reinstall; it must not be deleted merely because one setup disappears. Cancellation removes owned incomplete temporary files. Already published complete cache files can remain without a scene reference, avoiding unsafe cleanup of files needed by another scene or Redo. Cumulative disk retention and future explicit cleanup remain distinct from per-package admission.

Max must decode the prepared PNG on its host thread; the geometry/Paint snapshot avoids reopening their package files at commit. The bitmap adapter checks the owned file hash and actual colour interpretation again. Scoped Max 2027 tests pass shared diffuse/opacity/density identity, independent imported objects, coordinate/output/material values, decoded pixels, Undo/Redo and saved-scene reopening. The Scanline/Standard witness produces identical original/imported pixels and identical reopened pixels with both the original PNG and source package unavailable. This does not qualify Arnold, Corona, V-Ray, other material classes or arbitrary texture graphs. Earlier unpublished package prototypes do not have a compatibility guarantee; final installers will carry the frozen adapter.

## MAXScript admission and retired New Setup caches

Native-to-MAXScript hydration estimates its emitted tree before constructing output values. Large trees retain an 8-MiB reserve, with an Undo-preserving light collection before rejection. Imported authored data and later placement preparation have separate admission boundaries. Rejection is not permission to enlarge the artist's heap or discard Undo. Cached immutable schema rows avoid repeated conversion during capture. These are conservative, scoped safeguards; they do not guarantee every arbitrary SDK allocation or close the broader B26 issue.

A New Setup creation registers its new root, layers and Paint Area owners with a native Undo lifetime hook before they accumulate calculation data. Undo and Redo retain those caches. Only when Max discards an **undone** creation does the hook restore its captured initial transient cache locals; it skips owners still reachable from a scene node. This releases abandoned placement arrays retained by MAXWrapper lifetime without full GC, scripted destruction or scene mutation in a destructor. Add Layers and other general object lifetimes are outside this hook's tested scope.

Viewport display helpers can be removed on a deferred event-loop turn after Undo. Qualification waits for that boundary and still compares the full scene inventory, rather than ignoring helpers or manually deleting them. Exact pair-specific witnesses and failed predecessors are in PROGRESS_0851.md.

Scene departure is a separate lifetime boundary. Before open/reset/new detaches the graph, the script captures the departing roots, layers, Paint Areas and published owners. After departure it clears transient geometry/preparation/publication arrays only on captured owners with no live scene-node dependents. Current scene owners and ordinary usable Undo/Redo are retained. The final-script eight-example sequence asserts both complete imported results and released departed-owner arrays. This avoids retaining a departed scene's root publication merely because Max still retains a wrapper.


Final acceptance for the declared adapter is in [DELIVERY_0851.md](DELIVERY_0851.md) and [QUALIFICATION_0851.json](QUALIFICATION_0851.json). Earlier iteration paragraphs preserve their then-open status. The conservative Update admission also applies to ordinary explicit preparation, so it may reject a workload the preceding build attempted. The current 60,000-row/100-MiB-heap rejection is documented rather than presented as a capacity improvement; broader B26 remains open.


## 0.86.2 density and transaction extension

Recipe format 6 appends nineteen typed image mapping/response/frame fields. Format 5 converts through explicit neutral UV/clamp defaults; scene schema stays 58. Local image frames are saved in world/metre space and rebased relative to the destination setup without moving its existing layers. Supported bitmap bytes, scalar interpretation, curves, image provenance, mesh/UV requirements and complete Paint are retained. Procedural graph portability requires an explicit linear 16-bit PNG snapshot; the editable producer is not claimed saved.

Preflight checks required channels for logical layers and their Paint Areas, texture UVs only in UV mode, saved local-frame validity, Paint compatibility, paths and package integrity before staging. Ready Load includes its first calculation and display preparation in the import hold. Late failure cancels staged assets/owners/publication; success is one Undo/Redo, including after source package files become unavailable. Library package status is a file-only manifest hint; full payload verification remains part of Load. See [executed scope](DELIVERY_0862.md).
