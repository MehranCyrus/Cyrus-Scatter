# I05 — predictable copy/import variation, Scatter 0.84.0

16 October 2026. This scoped delivery adds explicit variation policies while preserving independent ownership, supported authored settings and Paint. It follows [I04 / 0.83.0](I04_0830.md). The [active program](OBJECTIVE.md) continues; grids, later features, four additional examples and the EXE are incomplete. B26 remains an open heavy-scene Undo limitation.

## Artist workflow

- **Layers > Copy variation:** Same variation is the default; New variation chooses fresh receiver random inputs once. Both create independent owners, source/receiver correspondence and Paint data. Changing the dropdown is passive.
- **Recipes:** New variation remains the default. Saved variation retains the saved random inputs. Choose **Add layers**, or check **New setup** to use **Create new setup**. Existing destination layers remain intact.
- **Amount settings presets:** Saved seed, Keep current seed and New seed apply only their stated numeric seed policy. These presets do not contain a complete arrangement.
- Undo/Redo restores the chosen identities and variation without rerolling. Manual mode waits for Update; Live follows relevant dependencies. Max object Copy/Instance retains Max's existing ownership semantics.

An identical arrangement requires identical evaluated terrain, receiver history/slots, source order/weights, quantity/quotas, masks, Relax and collision context. Different models or terrain can change accepted results from the same saved random inputs. No source-reorder or arbitrary-topology invariance is promised. Paint still requires compatible receiver geometry, frame and saved units.

Named layer Copy now preserves additional Paint Area settings omitted by the preceding manual subset. Authored Scatter Edit and per-instance radius transfer remain I13 work; named Copy rejects those unsupported records instead of silently losing them. Max object Copy is the complete-setup duplication route. Complete recipe save retains its analogous guards.

## Persistence and performance boundary

Scene schema stays **58** with an appended variation parameter block. Complete recipes use **format/capability 3**, numeric settings remain **2**. Strict reads of recipe formats 1/2 derive variation from the original saved receiver identities before ownership remapping; format 1 also receives the preceding neutral orientation defaults. Original files, thumbnails and Paint payloads are not rewritten. See [format 3](FORMAT_3.md).

Each layer stores a bounded receiver random-domain array. Empty preceding scene data resolves to the existing receiver IDs; partial or invalid histories fail rather than reroll. Saving before the first Update enrolls correspondence metadata without evaluating terrain or calculating placements. Source correspondence and random domains remain separate.

Sampling, mesh density and slope/altitude stochastic filtering consume the same effective domain. Cache invalidation is per affected receiver. Nondefault domains enter the receiver binding **value**, preserving ownership keys and rejecting stale authored overrides. Default bindings retain their exact preceding representation.
