16 October 2026. Implemented and scoped Max 2027 checks passed. This is the first delivery of the [active program](OBJECTIVE.md), not completion of the remaining roadmap. Phase 6 is resumed. See [PROGRESS](PROGRESS.md) for the current task and Git checkpoint.

## Artist workflow

Open **Layers > Recipes...**. Choose **My recipes**, **Bundled examples**, or **Custom folder**. Search matches recipe/layer names, categories, descriptions and tags. Select a category to narrow the list. The summary identifies included layers, native Paint documents and external roles. Optional stored PNG thumbnails load for the selected entry and are reused; browsing never renders a new image.

To save, select the layers, name the recipe, optionally enter category/tags/description and choose **Use PNG thumbnail...**, then **Save Everything**. The thumbnail must be a PNG no larger than 1024 pixels on either axis and 2 MiB. Save writes a new recipe; unsupported authored Edit/radius data or nonstatic controllers produce an owner-specific explanation. Paint remains part of a complete save. Pending Manual settings are saved without calculating plants.

Choose **Review bindings**, explicitly bind the required scene objects/maps, and review **Match unique scene names** suggestions. **Import reviewed recipe** adds layers to the captured current setup. Check **New setup** to create a separate controller instead. One Undo/Redo covers the transaction. Receiver-bound Paint still requires compatible terrain, frame and saved units; substituting an unrelated mountain is not automatic Paint transfer.

**My recipes** uses `Documents/CyrusScatter/Library`. Bundled examples use `<Max user scripts>/CyrusScatter/Library-0.82.6.1`; saving while browsing them writes to My recipes. Their matching `.max` scenes are in that same installed folder. Open a copy of a scene to inspect a complete working example. The scene geometry is procedural and permitted for redistribution; substitute artist models through explicit bindings. This delivery does not import scene assets automatically.

Keep each `.csrecipe.json`, its optional `.library.json`, `thumbnail-*.png` and `paint-*.payload` directory together when sharing. Existing Amount/Transform settings presets remain accessible from this browser and retain their distinct format/location.

## Performance and correctness evidence

- File-only native worker: at most 10,000 recipes, 100,000 inspected entries, estimated 32 MiB indexed metadata and 128 visible rows. The worker uses no Max API or Paint payload hydration. Explicit Refresh rereads content, including same-size/same-time replacement. Search uses the in-memory index; no idle polling remains after a scan.
- Thirty local searches: median/p95 **4.42/22.50 ms** for 128 entries, **41.95/78.77 ms** for 2,000, **50.07/81.21 ms** for 10,000. Scan-start handlers measured 16.84/4.45/18.34 ms. Complete rows and terrain, calculation, preparation and upload counters stayed unchanged.
- Sixty open/scan/decode/close cycles in Live: median/p95 **288.44/354.28 ms** for the whole cycle. GDI/USER counts stayed at 1,240/1,295 from cycle 10 through 60. Private memory rose by 7,778,304 bytes after explicit collection; process handles rose by two. This is a bounded-cycle check, not proof of multi-hour stability. A separate **30.75-second idle** observation preserved every recorded work counter and complete row.
- Actual committed category selection, accented/Farsi names, duplicate names, uppercase extensions, stale metadata and corrupt image/Paint handling passed. Paint attachment corruption permits passive listing but rejects full read. A denied-write ACL produced an error without a new recipe or scene changes; ACLs were restored and existing file hashes verified. Localhost unavailable-share cancellation settled without scatter work. Arbitrary network behavior remains unqualified.
- Scripted layout bounds/overlap checks and visual captures passed at 100% and 150% Max UI scale. Physical 4K, mixed-monitor movement and input devices remain artist acceptance.
- Owned shutdown during an active 10,000-file scan exited in 5.28 seconds. The exit-code field is null; this proves observed process exit, not a numeric success code. Worker teardown occurs before DLL unloading.
- **34/34 native suites**, **166 Python tests**, and generated-script checks covering **281 controls** passed. [Qualification](QUALIFICATION_08261.json) pins raw receipts, source identities, actual loaded native/script pairs and limitations. Native-build receipt script identity precedes presentation fixes; final hosts independently pin the delivered script `580d3446773c85d91fd276a70d8e10e2e0c5de1bcc95b1deb056bc82c62be56b`.

Earlier compile/fixture failures remain in owned test directories. Python preparation sometimes leaves an enclosing Undo hold; the native transaction fixture explicitly cancels that private fixture hold and reloads the immutable scene before exercising real Undo/Redo. The product's hold guard is unchanged. An initial lifecycle fixture assumed `.NET Handle` needed `ToInt64`; pymxs already returned an integer. A denied-write fixture initially enumerated while the deny ACL was active; the successor verifies filesystem preservation after ACL restoration. Neither fixture failure required a product bypass.
