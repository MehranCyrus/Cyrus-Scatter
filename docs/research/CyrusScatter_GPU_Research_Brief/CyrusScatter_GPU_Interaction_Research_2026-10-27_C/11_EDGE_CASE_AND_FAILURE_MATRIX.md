# 11 — Edge cases and failure matrix

[Contents](00_README.md) · [Collision contract](05_COLLISION_AND_GUIDE_SOLVING.md) · [Lifetime rules](08_ASYNC_PUBLICATION_AND_LIFETIMES.md) · [Benchmark protocol](10_BENCHMARK_AND_VALIDATION_PLAN.md) · [Prototype specifications](14_MINIMAL_PROTOTYPE_SPECIFICATIONS.md) · [Distribution](15_DISTRIBUTION_FALLBACK_AND_ARTIST_WORKFLOW.md)

**This is a proposed validation matrix, not a table of GPU passes.** Execute a manageable core suite first; combine cases only when testing an identified interaction. Use seed `20261027`, metres, +Y up, identity positive-uniform transforms unless a row changes them, and record fixture fingerprints. Sphere controls use centre `(0,0,0)`, radius `1 m`; vary guide radius and Contact gap explicitly. Retain stable instance/guide/collider IDs in every diagnostic.

**Statuses:** *Proposed GPU behavior* means an implementation requirement still to validate; *Rejected initial profile* means admission must reject it; *Unknown until host probe* means public API or host behavior needs local proof; *Supplied CPU scope* records the supplied baseline only. An empty contact/surface-hit array alone never proves clear; only a complete admitted query with the required solid classification and candidate coverage may return clear. Incomplete, cancelled or unavailable queries never do. Failure retention must identify the last complete publication as stale relative to the edit.

## Execution and reporting

**F06 face-interior control — proposed, not executed.** Against the unit sphere at the origin, use triangle `(-2,-2,0.5), (2,-2,0.5), (0,2,0.5)`. All vertices and all three edges are outside the sphere; the closest slanted-edge distance is `sqrt(1.05) > 1`. Yet `(0,0,0.5)` is a point inside the triangle and inside the sphere. A supporting guide along its lower edge is clear for a sufficiently small guide radius/gap. The complete surface audit must detect the face-interior intersection. The executed X05 control has a penetrating leaf vertex and cannot by itself qualify this harder case.

Run geometry controls before performance cases, then lifetime fault injection, then host delivery. Reuse the same fixture fingerprints across CPU, CUDA, OpenCL and HLSL paths. The optional analytic checks cover selected principles; they do not qualify these GPU/host rows. Record expected versus observed status, completeness, publication ID, root/attachment/clearance errors, candidate counts, owned/scratch/retired bytes and recovery. A failure is actionable evidence; suppressing it by hiding extra vegetation, relaxing an unrecorded tolerance or discarding a slow sample invalidates the comparison.
