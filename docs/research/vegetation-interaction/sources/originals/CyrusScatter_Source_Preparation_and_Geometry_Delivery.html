01 / P / D / I / X

The product decision

Yes, for a declared asset contract: prepare the source once per accepted revision, then reuse its geometry-to-guide binding at every placement. An artist should not rig the same blade again merely because the scatter contains another copy. The difficult work is identifying the source’s parts and attachment semantics. Simple segmented ribbons can support bulk preparation; fused scans and cards can require corrections, authored guides or a lower preparation level.

The reusable record contains the immutable rest mesh, logical-to-render correspondence, semantic part IDs, roots, rest guides and frames, and binding coordinates. Each placement supplies its transform and a fitted guide state. This is a proposed product architecture, not a claim about private Cyrus code or an already implemented feature.

Three different costs remain: one-time source preparation, per-placement fitting, and final geometry delivery. Sharing the first does not eliminate the other two. A thousand distinct accepted bends can still require a thousand distinct position/normal arrays. A thousand identical bends can share one evaluated variant where the host and renderer support it.

The recommended first release accepts editable, segmented grass ribbons and reviewed disconnected clumps for independent fitting. Whole-clump bending supplies a clear fallback for cards and difficult clumps. Broad leaves and branching stems require an explicit advanced contract. Full geometry access is a prerequisite for deformation; a renderer proxy’s preview is insufficient.

What segmentation must mean

P — Keep three identities separate: (1) render corners/indices, (2) logical geometric vertices used for analysis, and (3) semantic blade/leaf/stem parts. Preserve the original mesh, UVs, smoothing/normal splits, face material IDs, and point order in the immutable source record. Store analysis equivalences in a side table.

Max's separate map indices illustrate why “split UV means separate blade” is false M02. Conversely, formats or renderers may expand one geometric position into multiple vertex records to carry different normals, UVs, or materials. If provenance provides a common source-vertex ID, the analysis can reunite these records without altering rendering. Without provenance, use conservative candidate seam pairs: coincident boundaries, compatible local edge order, consistent face orientation, and an explicitly allowed tolerance. Mark uncertain matches. Do not globally weld all nearby positions: adjacent blade roots and touching leaves can legitimately be coincident.

Connectivity should therefore run on the declared analysis topology. Use UVs as a supplementary direction cue only when the artist confirms that an axis means root-to-tip; mirrored islands, rotated atlases, overlapping UVs, and arbitrary unwraps break that assumption. The same rest displacement must be applied to verified duplicates, while retaining distinct face-corner UVs/normals/material assignments. If duplicate records have intentionally separate physical motion, they are separate logical vertices, even when coincident.

One evaluator applies at all three levels. Level 1 uses coarse drivers; Level 2 uses one framed guide per blade; Level 3 resolves a hierarchy and multiple guides before evaluating the same position mapping. The evaluator is not automatically equivalent to Skin, Skin Wrap or Point Deform. An imported bone/cage rig is accepted only if it can be converted into these drivers and weights and passes pose comparisons. Otherwise retain it as an authoring aid, bake a new rest source, or mark that behavior unsupported.

For a stone at the edge of a distant lawn, Level 1 may be visually sufficient. A close view of grass constrained between two stones generally needs Level 2 and final-surface contact checks. A broad fallen leaf curling over a curb needs widthwise degrees of freedom and sufficient tessellation; calling a single card’s centerline “advanced” does not provide them. These are shot-planning judgments, not measured accuracy claims.

Source preparation is not per-placement rigging

For a compliant source, the proposed logical operations are: select source → choose level → confirm roots and direction → review candidate parts/guides → inspect stress poses → accept preparation. Automatic analysis runs inside that flow. These are six UI tasks, not a measured click count. Corrections add work where ambiguity exists. A difficult source may need a guide for each blade once; the same source revision then reuses those guides at every placement.

04 / P / D

Preparation methods and ambiguity

The eight requested methods are evaluated below. All automatic recognition rules are proposals; named DCC capabilities are documented precedents. No private algorithm is inferred from an interface.

1. Root masks

Required information: accessible rest mesh; source units and frame; a selected root band, painted point mask, named vertex group, or imported data channel with an explicit semantic name. A height threshold is only a proposal when the plant is upright in the chosen source frame. In a curled or hanging plant, lowest position can be a tip.

Reliable inference: which records were marked and the connected support of the mask. An automatic root-plane guess cannot reliably distinguish a genuine base from a low-hanging leaf. Flag zero-root components, roots spanning most of a blade, multiple far-separated candidate roots, and roots lying away from the selected ground plane. The artist confirms or repaints once per source.

Preservation: a guide-root position pin fixes only the attachment location. A hard mesh-patch mask fixes every selected position and can also restrict orientation. Neither is a separately tunable angular-stiffness law. Store a separate root frame from an oriented root edge/patch or an artist arrow, and expose angular stiffness separately. Preserve rest curvature and width in the original geometry/binding, not in the mask. Use a finite root transition band if the selected visual model needs a soft attachment.

Seams and edits: propagate a mask over verified logical duplicates; show split copies with inconsistent values. Geometry identity/topology changes invalidate an index-based mask; spatial reprojection is a new, reviewable proposal. Material-only edits need not erase it. Attribute Paint's documented point-number requirement is a concrete precedent M04.

2. Connected-component analysis

Required information: declared analysis connectivity, optional authored part IDs, and a rule for excluding soil/debris. Reliable inference: graph components; not anatomical parts. Houdini can produce these IDs directly, and can optionally use UV connectivity instead M01.

Ambiguity detection: compare candidate components with root coverage, extent, branching topology, boundary count, and strip tests. One giant component in a clump, many tiny components on one apparent blade, or component roots missing entirely are review triggers. The artist merges logically split pieces, splits shared structures semantically, or chooses Level 1.

Preservation: no deformation is implied. Keep exact rest positions and channels; each accepted component can receive its own guide and frame. Part-scoped binding prevents a blade from being captured by its neighbor. Width and twist are still separate quantities to derive or author.

Seams and edits: component IDs recomputed from numbering are not stable asset IDs. Store durable semantic IDs and an explicit membership map. Recompute/review after connectivity, welding, separation, or index-order changes; UV-only changes matter only if UV connectivity was chosen.

3. Strip recognition

P — proposed algorithm, not an identified private Cyrus or DCC implementation. Require a narrow unbranched ribbon, meaningful longitudinal sampling, a confirmed root end, and no unresolved seam duplication. Candidate logic may identify longitudinal rings or pair opposing boundary samples, then average them into a rest centerline. Triangulated ribbons require recovering a coherent longitudinal ordering rather than treating every triangle diagonal as a branch.

Reliable inference: longitudinal order and paired width samples on assets that satisfy the declared strip model. This does not generalize to lobed leaves, stems with attachments, multiple crossed cards, or fused scans. Flag multiple root/tip choices, branching rings, holes, triangles spanning distant samples, negative/inconsistent signed widths, reversed parameter progression, or a centerline outside the intended blade. Artist supplies root/tip markers, seam/cut hints, or an authored curve.

Preservation: capture the actual curved rest centerline, cross-section offsets and frame field; reconstructing a straight generic ribbon would discard the source shape. Store asymmetry, width changes, thickness, and twist in residual offsets. The centerline alone cannot preserve which side of a twisted blade faces the camera.

Seams and edits: run on logical topology but bind every original render vertex/corner. Topology, rest-position, longitudinal UV, part membership, or root edits invalidate this result. The audit must distinguish “inadequately segmented for bend” from “recognition failed.”

4. Automatic centerline extraction

Required information: a specified algorithm and its admissible representation, root seeds, scale/noise assumptions, and branch semantics. Do not expose a universal “auto skeleton” without these qualifiers. A closed-surface contraction algorithm and an open-ribbon centerline algorithm solve different problems. CGAL's documented method requires a closed, single-component triangulated surface M03.

Reliable inference: a geometric curve graph for inputs accepted by that algorithm. Surface correspondence can be useful for initialization, but it does not label roots, stems, veins, or blade endpoints. Detect invalid input first, then branch count, short spurs, high residual-to-surface distances, competing graph paths, root reachability, and strong output changes under a declared analysis simplification. These are proposed diagnostics; no calibrated confidence probability is claimed.

Artist action: confirm root graph nodes and retained branches, delete spurs, join a missed branch, or replace a failed region with an authored curve. Record corrections once. A welded clump still needs a shared-junction policy.

Preservation: capture source curvature, asymmetric width/thickness and a twist frame separately. A curve skeleton is not a complete deformation coordinate system. Never cap a thin open blade solely to make a closed-mesh algorithm run and silently treat the resulting graph as authoritative. Store any such preprocessing and require review.

Seams and edits: analysis cleanup must have a map back to the immutable render mesh. Any changed cleanup, topology, branch selection, root, or source position requires re-extraction/rebind; material-only edits usually do not.

5. Authored curves

Required information: ordered root-to-tip curves in source space, stable curve/part IDs, a rest snapshot, an explicit root frame and/or up vector, and a declared capture scope. Curves can be authored by an artist, exported from a plant generator, or accepted after automatic extraction.

Reliable inference: user-supplied intent. Nearest point alone is ambiguous where a curve loops back or several curves overlap. Restrict capture by part and parameter region; show unbound vertices, assignments across boundaries, parameter reversals, and large residuals. Artist reverses a curve, adjusts placement, edits capture radii or part scope, and fixes its frame.

Preservation: use the rest curve and local residual offsets, not a straight-reference remapping unless that is explicitly intended. Tangent alignment does not fix rotation about the tangent; Wire Deform documents both tangent and tangent-plus-normal modes M06, and Orientation along Curve documents up-vector control M07. Wire Capture is a documented surface binding to curves with spatial falloff and groups M05.

Seams and edits: curve primitive reordering, changed sample IDs, rest-shape edits, and capture scope changes invalidate the stored binding. A stable ID or explicit remap is needed to carry it safely. Houdini Wire Deform itself requires matched rest/deformed primitive count and order M06. A purely UV/material edit can keep the geometry binding while refreshing channels.

6. Bones

Required information: a rest skeleton, hierarchy, root attachments, stable joint IDs and bind transforms; a weighted render mesh or a way to generate and inspect weights. Max 2027 Skin documents bone addition, reference pose and weight operations, including Voxel/Heat Map weighting M10. These operations are evidence of binding capabilities, not proof of vegetation-semantic rig discovery.

Reliable inference: weights from an already meaningful skeleton under that solver's assumptions. Flag zero-weight vertices, cross-blade influences, too many influences, mismatched bind transforms, unexpected scale, and joints off the intended stem. The artist fixes joints/hierarchy or paints/limits weights. A generator can create many blade chains procedurally; the artist need not manipulate each joint when the asset follows a contract.

Preservation: bind-pose transforms retain rest shape. Piece-scoped weights and root constraints retain attachment. Bending quality depends on longitudinal geometry and joint density; weight interpolation can change volume/width and requires a representative extreme-pose inspection. A root joint's position and angular behavior remain separate controls.

Seams and edits: duplicate logical vertices need consistent positional weights. Changes to bone IDs, hierarchy, bind pose, mesh membership/topology, or geometry positions require verified rebinding/remapping. Changing only animation poses does not redefine the rest binding. Skinning decomposition from a known animation sequence, such as Dem Bones, is not a substitute for preparing the original static plant M16.

7. Cages / surface drivers

Required information: a coarse surface or volume control mesh, matching rest and deformed driver topology, coverage of the render mesh, and explicit source-part capture limits. A cage can represent a whole clump, a broad leaf, or a stem assembly. For Point Deform, a line-only driver is specifically warned against because its local transforms can be unstable M08.

Reliable inference: proximity/shape influence, not biology. Flag render vertices outside capture, nearly collinear driver neighborhoods, implausibly distant weights, cross-part influence, inverted cage cells/faces, and changing driver topology. Artist modifies the cage, scope or weights; one cage per clump is intentionally less independent than one driver per blade.

Preservation: the detailed rest mesh supplies curvature and width; cage motion supplies a displacement field. A hard root mask or pinned driver patch preserves attachment. Broad leaf folding requires driver resolution across width; a single spine cannot express arbitrary surface folds. Twist follows the driver frame field and still needs suitable geometry. Preserve authored shading normals through the evaluator, rather than indiscriminately recomputing them as if they were ordinary smoothing normals.

Seams and edits: retain render channels and logical seam mapping. A changed render mesh can be recaptured to an unchanged cage, but that is a new binding to check. Changing the cage's connectivity or rest pose invalidates the capture. Skin Wrap documents reset/resampling in the undeformed pose and warns against topology-changing control objects M11.

8. Hybrid preparation

P — recommended product default. Start with authored metadata if present; otherwise make conservative component/strip/root proposals. Allow a root mask, root arrow, and a few replacement guides/cages only where needed. One source may contain Level 2 grass ribbons, a Level 3 broad leaf, and rigid seed heads. Distinct part types are stored as source data, then converted into the canonical evaluator's driver/binding representation.

Reliability comes from an explicit accepted partition and deterministic driver choice per region. Diagnose gaps, double ownership, incompatible shared vertices, unrecognized part types, and seams between two driver systems. Artist confirms the uncertain regions and shared transitions, rather than manually rigging every blade. Preserve full rest mesh residuals for all parts and use stable attachments for children.

Every accepted region records how it was made, its source dependencies, and the artist's corrections. Do not silently replace an authored curve with a new automatic guess after a source edit. Reuse regions whose dependencies are unchanged; mark affected regions stale.

Complement: preserve authored generator metadata

This is not another deformation solver. It supplies the missing semantic information: blade ID, root parameter, rest guide, width/frame, parent attachment, and material region. Exporting these once at asset creation is generally more defensible than reverse-engineering them later from triangles. Validate the declared schema, coordinate convention and revision. Do not interpret an unnamed vertex color or wind channel as a root mask without the artist/provider's definition. If a generator only exports render mesh, its internal hierarchy cannot be assumed to survive.

SpeedTree's documented pivots, growth-direction anchors, cutout controls and separate mesh asset levels illustrate that these semantics can exist during source authoring M12M13M14. The report does not claim that every standard export exposes them or that Cyrus can consume a proprietary format.

Two-sided geometry is another topology trap

I/X: Every OBJ triangle has exactly one mate with the same three position IDs and opposite winding. This test groups triangle position-ID sets and verifies the two permutations have opposite parity. It does not group approximately coincident positions. Raw position topology consequently reports 57 edges with more than two incident faces for grass and 12 for grass_leafs. Those are true raw counts; interpreting them as corrupt or branched botanical structure would overlook this explicit two-sided construction.

An analysis-only graph taking one representative of each pair has 66 and 18 triangles, respectively; it has no edge with more than two incident faces and preserves the 9 and 6 connected-component counts. No original face, UV, material, normal, or file is deleted or rewritten. Do not bake this diagnostic simplification into delivered geometry without an intentional material/sidedness conversion.

P: The preparation importer should keep a source-topology layer distinct from render-corner vertices, flag explicit opposite-winding pairs, and preserve a reversible render-to-logical correspondence. When only a render mesh is available, coordinate welding is an uncertain hypothesis to preview and confirm. A UV or normal split is not a blade boundary, and coincident positions are not proof of shared identity.

06 / P / X

One canonical guide-to-mesh evaluator

P — Canonical evaluator v1: fixed rest coordinates plus framed-guide offsets. The CPU function receives an accepted prepared source and an accepted guide pose. It produces owned positions, shading data, bounds and correspondence. It does not detect obstacles, solve contact, extract guides, read scene nodes or decide botanical parts. Those are upstream operations.

Data required for each logical geometric vertex

Symbol / fieldMeaning
p0[i]Immutable rest position in canonical source coordinates.
k, s[i,k], w[i,k]Guide ID, fixed normalized rest arc-length coordinate and nonnegative influence weight. Weights sum to one.
C0[k](s), R0[k](s)Rest guide center and proper orthonormal material frame. Its transverse axes carry width and thickness direction.
d[i,k]Full rest residual: transpose(R0[k](s)) × (p0[i] − C0[k](s)). Store all three components, including any longitudinal residual.
a[i]Optional rest-patch hold mask in [0,1]. One means hard hold; zero means full guide motion. It is distinct from the guide root anchor.
renderToLogical, corner tablesExplicit mapping back to original render positions and face-corner UV/normal/material data. Coincidence does not create this mapping automatically.

Position rule

q[i] = sum over influences k:
         w[i,k] * ( C[k](s[i,k]) + R[k](s[i,k]) * d[i,k] )

p[i] = a[i] * p0[i] + (1 - a[i]) * q[i]
worldPosition[j,i] = placementTransform[j] * p[i]

The placement transform is applied exactly once. Either solve against obstacles in world space with the correct transformed source metric, or transform them into the source metric consistently; nonuniform scale cannot be handled by pretending every collision radius remains unchanged. Reject singular transforms. Rest geometry is never overwritten with output positions.

The reference sampler stores strictly increasing knots from 0 to 1. It linearly interpolates centers, uses shortest-path quaternion SLERP for supplied transport directors, and linearly interpolates a separate unwrapped twist angle. Twist rotates about the guide frame’s local longitudinal axis. The same sampler is used at capture and evaluation. A fixed material coordinate never jumps to a newly nearest point after the guide bends.

The directors are explicit input data. This interpolation does not guarantee that the interpolated longitudinal axis equals the derivative of the piecewise-linear centerline. Preparation/driver validation must enforce the chosen alignment and sampling tolerance. A production driver may construct minimally twisting frames from a confirmed root transverse axis, then apply authored rest twist and solved twist; rotation-minimizing frames are a documented construction R01. The included script consumes supplied directors and does not implement that paper’s frame algorithm.

What is preserved, and under what conditions

  • Rest curvature and shape: if the accepted pose equals the stored rest centers and frames, every captured point reconstructs its original position within numerical tolerance. The source is not first straightened and then reconstructed from an ideal blade.
  • Width and thickness: with one guide, equal s, proper rotation and a=0, cross-section offsets rotate rigidly, so their mutual distances are preserved. Asymmetry and taper stay in the stored offsets. This does not promise preservation of all longitudinal edge lengths or surface area.
  • Twist: a tangent alone leaves rotation around that tangent undefined. Store a transverse root axis and a rest frame/twist field. Unwrapped angles retain complete turns that endpoint quaternion interpolation would otherwise lose. Flag zero-length spans, an undefined up direction, abrupt reversals and ambiguous twist signs.
  • Multiple-guide and soft-pin regions: both are linear blends and can shrink or collapse width. They do not guarantee volume preservation. Limit them to reviewed junction/transition regions, use representative extreme poses, and reject unacceptable area collapse or self-intersection.
  • Seams: evaluate each logical position, then send its displacement to its verified render duplicates. Keep their UVs, explicit normal indices and materials distinct. Deliberately independent coincident blades stay independent.

Normals and tangents belong to the canonical output

Select a normal policy once for the prepared source. In geometric mode, compute face normals from final triangles and produce corner normals using the recorded smoothing domains and hard boundaries. Degenerate faces are reported. This reflects the deformed surface, but it may change deliberately artistic foliage shading.

In authored-normal mode, the proposed v1 policy transports each original corner normal by its bound guide’s rest-to-current rotation. At blends, normalize the weighted sum of rotated normals, including any rest-patch hold contribution. Reject a near-zero sum. This is an explicitly chosen artistic normal transport, not the exact inverse-transpose of the spatial deformation Jacobian. Preserve the original corner-normal splits; do not silently replace this mode with smoothing. After either policy, use the placement inverse-transpose and normalize. Rebuild tangent frames from the final surface and retained UVs under a declared renderer-compatible tangent convention.

For a baked negative-determinant transform, permute triangle winding and all matching map/normal corner indices together; maintain tangent handedness. For a node transform that the renderer applies, use that adapter’s qualified handedness convention. Do not apply the reflection twice. Max’s normal representation and modifier support have documented pipeline caveats, so actual renderer and Bake preservation remain mandatory checks D09D21. The executed normal arithmetic checks cover placement transforms and geometric triangles only X01.

Collision and output validation

A collision-free centerline does not prove that a wide ribbon, its tip or its twist clears a stone. Build a conservative guide envelope from captured offsets, then validate the final deformed surface against the declared collision representation. If a root lies inside an obstacle or a gap is narrower than the accepted blade envelope, return a useful infeasibility/clearance diagnostic. Increasing iterations cannot create missing geometric freedom.

Compute final bounds from the evaluated vertices, including all parts. Expand them only for declared renderer displacement or motion requirements. A static initial product can explicitly omit deformation motion blur; if animation is supported later, publish complete time samples with stable topology and qualify every delivery path. Do not synthesize motion blur from stale guide states.

Executed here: ten supplied-binding arithmetic checks confirm rest identity, a hard patch hold, the restricted single-guide width property, twist winding, seam correspondence, placement normals, mirror winding, vertex bounds and the root-location/orientation distinction. An opposing-guide example deliberately demonstrates blend collapse. These checks are evidence about this mapping’s arithmetic, not about automatic preparation or fitting X01.

"""Cyrus preparation study: proposed CPU guide evaluator, not a Max plug-in.

Python 3, standard library only. Run: python reference_evaluator.py
The generated JSON records arithmetic checks, not DCC, renderer or speed tests.
This evaluates already-authored bindings. It does not extract or fit guides.
"""
from math import acos, cos, sin, sqrt, pi
from pathlib import Path
import json

EPS = 1e-12

def add(a, b): return tuple(x + y for x, y in zip(a, b))
def sub(a, b): return tuple(x - y for x, y in zip(a, b))
def mul(a, t): return tuple(x * t for x in a)
def dot(a, b): return sum(x * y for x, y in zip(a, b))
def cross(a, b): return (a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0])
def norm(a): return sqrt(dot(a, a))
def unit(a):
    n = norm(a)
    if n < EPS: raise ValueError('Zero vector / invalid frame')
    return mul(a, 1 / n)
def mix(a, b, t): return add(mul(a, 1-t), mul(b, t))
def qmul(a, b):
    w, v, z, t = a
    x, y, r, s = b
    return (w*x-v*y-z*r-t*s, w*y+v*x+z*s-t*r,
            w*r-v*s+z*x+t*y, w*s+v*r-z*y+t*x)
def qconj(q): return (q[0], -q[1], -q[2], -q[3])
def qrotate(q, v): return qmul(qmul(q, (0, *v)), qconj(q))[1:]
def qaxis(axis, a): return (cos(a/2), *mul(unit(axis), sin(a/2)))
def qslerp(a, b, t):
    a, b = unit(a), unit(b)
    d = dot(a, b)
    if d < 0: b, d = mul(b, -1), -d
    d = max(-1, min(1, d))
    if d > .9995: return unit(mix(a, b, t))
    th = acos(d)
    return add(mul(a, sin((1-t)*th)/sin(th)), mul(b, sin(t*th)/sin(th)))

def sample(guide, s):
    """Linear center; SLERP transport; linear UNWRAPPED twist, rest-s knots.

    Transport quaternions and twist are separate. The binding coordinate s is
    never reprojected onto the deformed guide. Zero-length center spans and
    transport construction are preparation/driver validation responsibilities.
    """
    knots = guide['knots']
    if not 0 <= s <= 1: raise ValueError('Binding coordinate outside [0,1]')
    if len(knots) < 2 or knots[0] != 0 or knots[-1] != 1:
        raise ValueError('Guide needs endpoints 0 and 1')
    if any(b <= a for a, b in zip(knots, knots[1:])):
        raise ValueError('Guide knots must increase strictly')
    k = next((k for k in range(len(knots)-1) if s <= knots[k+1]), len(knots)-2)
    t = (s - knots[k]) / (knots[k+1] - knots[k])
    c = mix(guide['centers'][k], guide['centers'][k+1], t)
    q = qslerp(guide['transport'][k], guide['transport'][k+1], t)
    theta = (1-t)*guide['twist'][k] + t*guide['twist'][k+1]
    return c, unit(qmul(q, qaxis((0,0,1), theta)))

def capture(p0, influences, rest_guides, pin=0):
    """influences: (guide_id, fixed rest-s, nonnegative normalized weight)."""
    if not 0 <= pin <= 1: raise ValueError('Pin mask outside [0,1]')
    if not influences or min(w for _, _, w in influences) < 0:
        raise ValueError('Missing or negative weights')
    if abs(sum(w for _, _, w in influences)-1) > 1e-10:
        raise ValueError('Weights must sum to one')
    bind = []
    for key, s, weight in influences:
        c0, q0 = sample(rest_guides[key], s)
        d = qrotate(qconj(q0), sub(p0, c0))
        bind.append(dict(guide=key, s=s, weight=weight, offset=d))
    return dict(rest=tuple(p0), pin=pin, influences=bind)

def evaluate(binding, guides):
    q = (0., 0., 0.)
    for inf in binding['influences']:
        c, rot = sample(guides[inf['guide']], inf['s'])
        q = add(q, mul(add(c, qrotate(rot, inf['offset'])), inf['weight']))
    return mix(q, binding['rest'], binding['pin'])

def triangle_normal(p): return unit(cross(sub(p[1],p[0]), sub(p[2],p[0])))
def box(points): return ([min(p[k] for p in points) for k in range(3)],
                         [max(p[k] for p in points) for k in range(3)])

def run_checks():
    identity = (1.,0.,0.,0.)
    straight = dict(knots=[0.,1.], centers=[(0.,0.,0.),(0.,0.,1.)],
                    transport=[identity,identity], twist=[0.,0.])
    curved = dict(knots=[0.,.5,1.], centers=[(0.,0.,0.),(.2,0.,.45),(.5,.1,.8)],
                  transport=[identity,qaxis((0,1,0),.4),qaxis((0,1,0),.8)],
                  twist=[0.,.7,2.2])
    bent = dict(knots=[0.,1.], centers=[(0.,0.,0.),(.7,.2,.65)],
                transport=[identity,qaxis((0,1,0),.9)], twist=[0.,1.4])
    out = []
    def record(key, name, metric, tolerance, passed, scope):
        out.append(dict(id=key,name=name,metric=metric,tolerance=tolerance,
                        passed=passed,scope=scope))
        assert passed, name

    # Rest curvature + twist identity, including a blended binding and soft pin.
    errors=[]
    for s in [0.,.125,.4,.5,.7,1.]:
        p=(.1+s*.3,.04,s*.8)
        b=capture(p,[('a',s,.35),('b',s,.65)],{'a':curved,'b':straight},pin=.23)
        errors.append(norm(sub(evaluate(b,{'a':curved,'b':straight}),p)))
    record('E01','Rest pose identity with curvature, twist and blended weights',
           max(errors),1e-12,max(errors)<1e-12,'Arithmetic only; supplied binding')

    b=capture((.07,0.,0.),[('g',0.,1.)],{'g':straight},pin=1.)
    err=norm(sub(evaluate(b,{'g':bent}),b['rest']))
    record('E02','Hard root patch vertex remains fixed',err,0.,err==0.,
           'Pin mask only; angular stiffness is not simulated')

    widths=[]
    for s in [.125,.4,.75,1.]:
        positions=[]
        for x in [-.06,.06]:
            c,q=sample(curved,s)
            p=add(c,qrotate(q,(x,0.,0.)))
            b=capture(p,[('g',s,1.)],{'g':curved})
            positions.append(evaluate(b,{'g':bent}))
        widths.append(abs(norm(sub(*positions))-.12))
    record('E03','Single-guide cross-section width preserved',max(widths),1e-12,
           max(widths)<1e-12,'One influence, equal s, pin=0, orthonormal frames')

    twist=dict(straight,twist=[0.,4*pi])
    _,q=sample(twist,.125)
    error=norm(sub(qrotate(q,(1.,0.,0.)),(0.,1.,0.)))
    record('E04','Two full turns retain the intermediate 90-degree twist',error,
           1e-12,error<1e-12,'Unwrapped angle interpolation, not quaternion winding inference')

    # Render splits are an explicit mapping, never proximity inferred here.
    analysis=[capture((-.1,0.,0.),[('g',0.,1.)],{'g':straight}),
              capture((.1,0.,1.),[('g',1.,1.)],{'g':straight})]
    deformed=[evaluate(b,{'g':bent}) for b in analysis]
    mapping=[0,1,0,1]
    render=[deformed[i] for i in mapping]
    uv=[(0.,0.),(1.,1.),(.5,0.),(.5,1.)]
    ok=render[0]==render[2] and uv[0]!=uv[2]
    record('E05','Render-position duplicates move together while UVs stay split',
           {'render_vertices':4,'analysis_vertices':2},None,ok,
           'Explicit correspondence, not an automatic weld')

    p=[(0.,0.,0.),(1.,0.,1.),(0.,1.,1.)]
    n=triangle_normal(p)
    scale=(2.,.5,3.)
    pp=[tuple(x*y for x,y in zip(v,scale)) for v in p]
    actual=triangle_normal(pp)
    expected=unit(tuple(x/y for x,y in zip(n,scale)))
    err=norm(sub(actual,expected))
    record('E06','Nonuniform placement normals use inverse transpose',err,1e-12,
           err<1e-12,'Geometric triangle normal; shader and explicit normal export untested')

    mirrored=[(-v[0],v[1],v[2]) for v in p]
    corrected=triangle_normal([mirrored[i] for i in [0,2,1]])
    err=norm(sub(corrected,(-n[0],n[1],n[2])))
    record('E07','Baked mirror needs reversed triangle corner order',err,1e-12,
           err<1e-12,'All map/normal corner indices must follow the same permutation')

    positions=[evaluate(capture((x,0.,s),[('g',s,1.)],{'g':straight}),{'g':bent})
               for s in [0.,.2,.5,.8,1.] for x in [-.1,.1]]
    low,high=box(positions)
    ok=all(low[k]<=p[k]<=high[k] for p in positions for k in range(3))
    record('E08','Published bounds contain all evaluated mesh positions',
           {'min':low,'max':high},None,ok,'Static mesh only; no renderer displacement expansion')

    plus=dict(straight,transport=[qaxis((0,0,1),pi/2)]*2)
    minus=dict(straight,transport=[qaxis((0,0,1),-pi/2)]*2)
    b=capture((1.,0.,1.),[('a',1.,.5),('b',1.,.5)],{'a':straight,'b':straight})
    length=norm(sub(evaluate(b,{'a':plus,'b':minus}),(0.,0.,1.)))
    record('E09','Expected limitation: opposing blended frames collapse width',
           {'remaining_radius':length,'rest_radius':1.},1e-12,length<1e-12,
           'Counterexample; no general volume/width preservation for multiple guides')

    a0=sample(straight,0.)[0]
    lean_rotation=qaxis((0,1,0),pi/4)
    leaned=dict(straight,centers=[(0.,0.,0.),qrotate(lean_rotation,(0.,0.,1.))],
                transport=[lean_rotation]*2)
    a1=sample(leaned,0.)[0]
    t0=qrotate(sample(straight,0.)[1],(0.,0.,1.))
    t1=qrotate(sample(leaned,0.)[1],(0.,0.,1.))
    ok=a0==a1 and norm(sub(t0,t1))>.1
    record('E10','Fixed guide root position does not determine its orientation',
           {'anchor_displacement':norm(sub(a0,a1)),'tangent_difference':norm(sub(t0,t1))},
           None,ok,'Constraint distinction; not a physical root solver')
    return {'status':'passed','check_count':len(out),'checks':out,
            'excluded':['Max runtime','renderer output','collision fitting','automatic extraction',
                        'preparation time','performance benchmark'],
            'implementation':'Proposed reference evaluator, Python standard library'}
