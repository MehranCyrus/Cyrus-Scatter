## Performance interpretation

The baseline already avoided repeated solves in the tested simple idle scene. The improvement removes repeated host checks and the demonstrated Manual-mode notification loop; it is not a claim that every earlier slowdown was a full recalculation.

Recording overhead uses interleaved off/on trials in one warmed 600-candidate scene, 24 edits per condition. Final medians were 266.0 ms off and 271.5 ms on (about 2.1% higher for this sample); the preceding repeat measured 270/270 ms. See `idle-qualification.json` for all final samples. This bounds an observed workload; it does not prove zero overhead for dense sources, long Brush histories or many controllers. Native recording is opt-in, bounded and memory-only on event paths; export is an explicit operation. The courtyard IR trace contained 266 events / 69,032 bytes with no reported eviction, lock drop, recording failure or truncation.

Whole-Max CPU remains nonzero in private idle measurements. It includes Max, other plugins and ordinarily the development transport's 200 ms polling. A separate 12.004-second observation stopped that transport throughout the window: the process still consumed 2.031 seconds of CPU, while all measured Cyrus counters stayed unchanged (`transport-paused-verified.json`). Thus remaining process activity cannot simply be attributed to that transport or to repeated scatter evaluation. No GPU time, presentation FPS, per-plugin CPU attribution or universal memory bound is inferred from these numbers.

## Diagnostics and MCP result

The Automation panel can start/stop an engineering recording and save a local JSON report. Its default recording is capped at ten minutes, 4,096 events and 4 MiB; exports include health/loss counters and build identity. Reading that process-wide trace through MCP requires a separate local sharing grant. Recording, sharing and training eligibility remain distinct. Reports are not automatically uploaded or placed into an artistic dataset.

Policy 3 remains read-only through MCP. The capability catalog describes native features and unsupported operations without making arbitrary script execution available. Existing closed plans 1/2 retain their established behavior. The offline `3.0-draft1` compiler, study journal and experimental preference baseline do not provide a qualified policy-3 write adapter, renderer worker, image-composition model or trained production ML system.
