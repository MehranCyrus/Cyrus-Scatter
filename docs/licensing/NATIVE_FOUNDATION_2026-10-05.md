# Native ownership and local licensing foundation — 5 October 2026

**Qualified development foundation; commercial system incomplete. No product installation or customer issuance.** This supersedes current-status statements in the earlier experiments, not their historical receipts. Product source remains 0.7.0. The ordinary build does not enable licensing enforcement or trust a development issuer.

## Implemented boundary

An opt-in native experiment owns amount, seed, receiver reference and admitted revision in a private `ReferenceTarget`. Evaluation accepts only that owner; it cannot receive a new amount/seed or a caller-supplied “saved evaluation” flag. Authoring validates a prospective calculation before committing, with a native single-use permit checked at commit. Save/load and Undo restore native state; they do not require a currently active authoring grant.

The real CS Edit mutation methods now have an opt-in boundary before reset/delete/clone/transform and Undo capture. The experiment also checks the simple raw generator. A separate diagnostic calls the actual SDK Move callback, bypassing the MAXScript command wrapper. Selection, identity evaluation, restore and drawing remain separate.

The native Brush document now admits creation, settings, fill, history edits/deletion and strokes through the same native client in AminScatter. Brush imports the gate instead of creating a second session. A gesture holds a move-only permit; the actual Painter `EndStroke` callback consumes it before Undo capture/publication. Expiry cancels pending samples and preserves completed history. Stop/cancel, read/display, save/load and Undo/Redo remain available. The direct Dab primitive also now respects failed start/commit callbacks and its existing sample bound in ordinary builds; it previously returned success after ignored callback failure.

This proves a **bounded ownership design**, not full product enforcement. Advanced/procedural generation, full layer settings, Analyzer dependencies, source/container enrollment, PFlow/bake preparation and legacy migration have not moved into this owner. Brush's stored history has mutation gates, but raw filter inputs, external receiver changes and SDK scene cloning are not authenticated full recipes. Existing `.max` class IDs are unchanged; the new private experiment class is registered only in the experiment build. Native chunk persistence is not cryptographically authenticated scene provenance. A hostile modified scene file and arbitrary native-code injection remain outside the demonstrated boundary.

The simpler workflow-lock alternative would touch fewer paths but would retain the known public compute/parameter bypasses. Extending native ownership requires a complete authored recipe and a deliberate old-scene migration contract. Do not turn on the partial gate in a customer build: that would both leave bypasses and risk breaking legitimate cold rendering.

## Foundation beyond the ownership slice

- `LicenseSession` publishes immutable verified claims through an atomic shared snapshot. Concurrent import cannot expose partial state. A rejected import retains the last accepted grant.
- `OperationPermit` is move-only, native-local, owner/session/operation-bound and consumed on every commit attempt. The maximum requested lifetime is 30 seconds, clipped conservatively before signed expiry. Renewal cannot extend an old in-flight permit. No permit is persisted or exposed as a script boolean.
- CNG creates a per-Windows-user software P-256 installation key with private export disabled. Activation proves possession using a nonce/account/tenant/product-bound challenge. The device ID is a domain-separated SHA-256 of its public coordinates. This is installation identity, not hardware attestation or a guarantee against an administrator extracting software secrets.
- Local state uses current-user DPAPI, bounded schema validation, an exclusive interprocess file lock, flushed temporary writes and replacement. Failed/cancelled writes keep the preceding state. Missing, unreadable and mismatched-device state are distinct recovery cases. A complete old protected backup can still be replayed across restarts; the tests explicitly demonstrate that limitation.
- `ClockTracker` combines protected highest-observed UTC with a sleep-inclusive native monotonic clock. It detects tested rollback and large in-process forward changes and latches recovery. Closed-app calendar time is included without periodic mandatory refresh. An offline software clock cannot prove that an entire installation/clock snapshot has not been restored.
- `LocalLicenseClient` provides request/activation/import/status/refresh/checkpoint. Initial time confidence requires a separate, signed, fresh-nonce activation response. A license's `nbf` is not treated as current time. Imports preserve device/account/product/build scope; a bad or older-shorter renewal does not replace useful authority. Ordinary decisions/admission perform no network, disk or signature work after initialization.
- File/key/import work uses a separate lifecycle mutex. Clock decisions hold only a short memory lock; verified publication adopts an internally verified immutable snapshot. A real file-lock contention test would block the original shared-lock implementation and now completes 2,000 decisions/commits in 0.2802 ms while the checkpoint waits independently.
- The private issuer is a separate Python cryptography process. Its private key exists only in memory. It verifies device proof but intentionally has no customer authentication, purchased-seat ledger or commerce. Its synthetic account is not a deployable service.

The native Max adapter has two mutually exclusive development contexts: the original deterministic clock fixture, and a real installation-key/DPAPI/UTC context. The latter does **not** register the synthetic clock primitive. Both are default-off and labelled NEVER SHIP. Product packaging explicitly disables the experiment and refuses development markers in binary payloads. Eight checks against actual ordinary/lab binaries passed; no package was created by this guard test.

## Decisions and remaining scope

B07 and B08 have been presented to the user with concrete options; they remain OPEN until answered. Source geometry, receiver changes and animation alter evaluated geometry while the native authored recipe remains unchanged. The recommended continuity contract preserves the Cyrus recipe and permits dependency evaluation; freezing the entire evaluated world would require another storage and missing-asset design.

The real-key two-installation experiment also demonstrates B08: giving B a fresh full-term grant cannot cancel disconnected A's existing signed permission. Immediate reuse therefore accepts potential overlap. Strict non-overlap requires accounting for A until its last outstanding permission ends. No shorter mandatory offline window has been introduced.

Customer authentication, transactional assignment/issuance, transfer policy, production trust/signing custody, authenticated clock recovery after loss/rollback, whole-product native coverage, final package signing, renderer coverage and Max 2026 runtime remain release gates. The two-module experiment shares one runtime, but this C++ interface is not yet a stable cross-version ABI. The foundation is not described as a finished commercial licensing system.

The private adapter now refreshes/checkpoints on a 60-second background interval and at clean shutdown. This is local disk maintenance, not a mandatory online refresh or a shortened license term. The worker accesses only the local client, never Max nodes/UI, and exposes cycle/error diagnostics. `NOTIFY_SYSTEM_SHUTDOWN` and idempotent `LibShutdown` cleanup join it outside `DllMain`. A forced process kill can lose observations since the last checkpoint; restoring a complete old installation can still replay authority. The file-lock wait is bounded, but underlying OS disk/crypto calls are not cancellable hard real-time operations. The clean measured shutdown does not qualify every disk fault or a strict maximum host-exit delay. Initial key/store loading and explicit development import remain synchronous; production recovery/background UX still needs qualification.

## Primary API contracts

[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) documents current-user protection and roaming-profile exceptions; it is not a unique physical-machine guarantee. [Windows elapsed time](https://learn.microsoft.com/en-us/windows/win32/sysinfo/windows-time) documents native `GetTickCount64` including sleep/hibernation. [CNG key properties](https://learn.microsoft.com/en-us/windows/win32/seccng/key-storage-property-identifiers) describe export policy and key usage. Native persistence was checked against the local SDK's typed `ISave`/`ILoad` interfaces, not assumed from an older generic `void*` overload.

[Autodesk's DLL lifecycle contract](https://help.autodesk.com/cloudhelp/2023/ENU/Max-Developer-Help/writing_plug-ins/creating_a_plug-in_project/manually_creating_a_new_plug-in_/required_dll_functions.html) directs substantial initialization/cleanup away from `DllMain`. The SDK 2026/2027 notification headers and [shutdown notifications](https://help.autodesk.com/cloudhelp/2025/ENU/MAXDEV-CPP-API-REF/group___notification_codes.html) informed the adapter's main-thread lifecycle hooks. These API contracts support the design; the private clean-shutdown test supplies the actual runtime evidence.
