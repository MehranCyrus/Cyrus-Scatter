# 04: Surfaces and Areas

## 1. Purpose and scope

This specification defines the surface input model, surface hit resolution, the ordered Area Program, area masks, filters, and boundary checks. It implements stages S2, S3, and S8 in `00_ARCHITECTURE.md`, and it defines the data that S4 consumes. It is written for the Cyrus Scatter core in C++20, with a thin Max adapter that builds immutable snapshots on the main thread.

The goals are to match the documented Forest Pack behavior where that behavior is public, while making every private or ambiguous choice explicit. A surface is both a placement substrate and, optionally, an Area Program entry. An area is an ordered operation that can include candidates, exclude candidates generated by lower entries, or provide a mask and falloff source. Areas do not generate model geometry themselves: S1 creates stable candidate coordinates, S2 resolves a surface hit, S3 applies area membership and filters, S4 applies falloff, S6 chooses a model, S7 computes the final transform, and S8 checks the item footprint against its boundary.

In scope:

* Surface lists, linked surfaces, Get From Forest, ForestSet-like collections, shared surface acceleration caches, and invalidation.
* XY and UV surface modes, stacked hits, back-face policy, Direction, tangent frames, and Scale to fit sloped areas.
* Surface filters: altitude, slope, and Material ID.
* Surface as an Area with an On toggle and a boundary derived from mesh border edges.
* The bottom-to-top Area Program, Include and Exclude semantics, area identity, `areaIndex`, common properties, and linked areas.
* Spline, Object, Forest, Surface, Linked, and Paint area query contracts.
* S8 Point, Size, and Edge boundary checking, including `F_EDGE_CLIP` and render-time trimming.
* UI list behavior, dirty bits, tests, failure modes, and performance targets.

Paint storage and evaluation are specified in `05_FALLOFF_PAINT.md`. The existing surface-anchored Cyrus paint engine is the implementation for a Paint area. Geometry diversity, collisions, transforms, camera culling, and render integration are specified by later files.

**Why this split matters:** generation coordinates, surface attachment, and region membership are separate concerns. It permits the same surface hit to feed slope filtering, material filtering, normal alignment, boundary distance, and paint coverage without repeated ray casts or inconsistent answers.

## 2. Forest Pack behavior to match

The following are behavior claims from the research notes and public references. They are not claims about Forest Pack's private data structures.

* **[FP-DOC]** The Surfaces list accepts mesh terrain and places items along the surface object's local Z axis. The list has Add, Add Multiple, Delete, and Get From Forest. Source: [Surfaces](https://docs.itoosoft.com/forestpack/forest-plugin/surfaces).
* **[FP-DOC]** Get From Forest uses all surfaces referenced by another Forest object. Forest Pack 8 added linked surfaces and areas, with source type parameters inherited and common Include, Exclude, and Falloff properties local to the child. Sources: [Surfaces](https://docs.itoosoft.com/forestpack/forest-plugin/surfaces), [Forest Pack 8 changes](https://docs.itoosoft.com/forestpack/whats-new/forest-pack-8).
* **[FP-DOC]** A ForestSet may provide all compatible surfaces, splines, object areas, or other accepted inputs. A Set can be shared, populated with Add Multiple or named layers, and nested. Source: [ForestSet](https://docs.itoosoft.com/forestpack/forestset-plugin).
* **[FP-DOC]** XY mode generates in Forest local XY and moves each item along the surface local Z. UV mode uses surface UVs for placement and is intended for vertical or convex surfaces. Sources: [Surfaces](https://docs.itoosoft.com/forestpack/forest-plugin/surfaces), [Image Mode](https://docs.itoosoft.com/forestpack/forest-plugin/distribution/image-mode).
* **[FP-DOC]** Direction ranges from -100, Down, through 0, Normal, to +100, Up. Scale to fit sloped areas is for XY mode and aligns to the normal. Its exact interpolation formula is not published. Source: [Surfaces](https://docs.itoosoft.com/forestpack/forest-plugin/surfaces).
* **[FP-DOC]** Non-Image modes can Link to Surface to update item Z, while a surface can also supply color or texture information without moving an item when Link to Surface is off. Custom Edit uses Link to Surface for placement, otherwise Place Trees is used manually. Sources: [Surfaces](https://docs.itoosoft.com/forestpack/forest-plugin/surfaces), [Forest Color](https://docs.itoosoft.com/forestpack/forest-color), [Items Editor](https://docs.itoosoft.com/forestpack/forest-plugin/item-editor).
* **[FP-DOC]** Altitude has a Limited switch and Bottom and Top bounds. Slope Angle Range limits the surface slope from horizontal, 0 degrees, to vertical, 90 degrees. Exact defaults are not public. Source: [Surfaces](https://docs.itoosoft.com/forestpack/forest-plugin/surfaces).
* **[FP-DOC]** Area Material ID filters surface faces by material ID. It requires a surface and XY mode in Forest Pack. Source: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas).
* **[FP-DOC]** Randomize Stacked changes random behavior for candidates at the same XY location on stacked surfaces. Separate Sub-Splines treats sub-splines as individual areas. Sources: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas), [Forest Pack 9 beta](https://forum.itoosoft.com/announcements/forest-pack-9-beta-with-max-2025-support-forestivy-and-more/).
* **[FP-OBS]** Support reports that stacked surfaces need separate objects and that Falloff and Edge boundary features may disable stacked-surface behavior. Cyrus therefore supports stacked hits explicitly but reports compatibility diagnostics rather than silently collapsing them. Sources: [Randomize stacked issue](https://forum.itoosoft.com/forest-pro-(*)/randomize-stacked-issue/), [Stacked surfaces](https://forum.itoosoft.com/forest-pro-(*)/scattering-on-stacked-surfaces-not-working-in-xy-surface-mode/).
* **[FP-DOC]** A surface is also an Area entry that can be On or Off. Leaving it On while adding a spline Include can populate the whole surface. A surface Area has a virtual boundary extracted from closed mesh edges, which may be imperfect. Sources: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas), [Rendering best practice](https://docs.itoosoft.com/forestpack/rendering/rendering-best-practice).
* **[FP-DOC]** Areas are ordered bottom to top. Excludes affect items generated by lower Areas. Common properties include On, Name, Select Models, per-area Scale, Override Distribution Map, Material ID, Falloff Affect, Invert Curve, Boundary Checking, Project Axis, Randomize Stacked, and Separate Sub-Splines. Source: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas).
* **[FP-DOC]** Spline areas support closed splines, open splines with Thickness, Force Open Splines, and Separate Sub-Splines. The full versus half-width convention for Thickness is **[OPEN]**. Source: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas).
* **[FP-DOC]** Object areas are Exclude-only, rasterized along world Z, with Resolution default 512, Scale, and Top Limit. Forest areas are Exclude regions from another Forest, with Sphere or Mesh shape, Resolution default 512, and Scale. Sources: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas).
* **[FP-DOC]** Linked Object areas are Exclude-only. Linked type parameters are inherited, but common properties are local. Source: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas).
* **[FP-DOC]** Paint areas support Include and Exclude, but must use a Surface in XY mode. The Surface Area is normally turned Off when the painted region is intended to be the boundary. Source: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas).
* **[FP-DOC]** Boundary modes are Point, Size, and Edge. Point tests the pivot, Size uses item width and collision radius, and Edge trims outside elements at render time for supported renderers. Sources: [Areas](https://docs.itoosoft.com/forestpack/forest-plugin/areas), [Rendering best practice](https://docs.itoosoft.com/forestpack/rendering/rendering-best-practice).

Forest does not publish the exact overlap algebra for Includes, exact surface-hit tie-breaks, back-face policy, open spline Thickness convention, or its private cache keys. Those choices are marked **[OPEN]** or **[DESIGN]** below.

## 4. Data structures

All types in this section live in `core/` and contain no Max headers. They extend `00_ARCHITECTURE.md`; they do not redefine `Population`, `StageContext`, `StableKey`, `KeyParts`, `DirtyBits`, or `SharedCacheRegistry`.

```cpp
namespace cyrus {

enum class SurfaceMode : u8 { XY, UV };
enum class BackFacePolicy : u8 { FrontOnly, DoubleSided, Explicit };
enum class AreaOp : u8 { Include, Exclude };
enum class AreaType : u8 { Spline, Object, Forest, Surface, Linked, Paint };
enum class BoundaryMode : u8 { Point, Size, Edge };
enum class ForestShape : u8 { Sphere, Mesh };
enum class AreaProjectAxis : u8 { X, Y, Z };

typedef u32 SurfaceEntryId;
typedef u32 AreaEntryId;

struct SurfaceRef {
    SurfaceEntryId entryId;
    NodeSnapshotId node;          // opaque L3 handle, not an INode pointer
    u32 uvChannel;
    bool fromForest;
    bool linked;
    u32 sourceForestId;
    std::vector<NodeSnapshotId> expandedNodes; // immutable snapshot result
};

struct SurfaceParams {
    SurfaceMode mode;
    AreaProjectAxis uvProjectAxis;
    int direction;                 // -100 to 100
    bool fitSlope;
    bool linkToSurface;
    BackFacePolicy backFace;
    bool altitudeLimited;
    double altitudeBottom, altitudeTop;
    bool slopeLimited;
    float slopeMinDeg, slopeMaxDeg;
};

struct SurfaceHit {
    bool valid;
    SurfaceEntryId surfaceEntry;
    u32 faceIndex;
    double rayT;
    Vec3d worldPos;
    Vec3d flPos;
    Vec3d normalFL;
    Vec3d tangentFL, bitangentFL;
    Vec3f uvw;
    u16 materialId;
    float slopeDeg;
    float altitude;
    u32 layer;
    bool backFace;
};

struct AreaCommon {
    AreaEntryId entryId;
    bool on;
    AreaOp op;
    std::string name;
    SmallVector<u32, 4> modelEntryIds;
    float areaScale;
    DistributionMapOverride mapOverride;
    SortedSmallSet<u16, 8> materialIds;
    float falloffAffect;
    bool invertCurve;
    BoundaryMode boundary;
    AreaProjectAxis projectAxis;
    bool randomizeStacked;
    bool separateSubSplines;
};

struct AreaDef {
    AreaType type;
    AreaCommon common;
    SplineAreaParams spline;
    ObjectAreaParams object;
    ForestAreaParams forest;
    SurfaceAreaParams surface;
    LinkedAreaParams linked;
    PaintAreaRef paint;
};

struct AreaMaskSample {
    bool inside;
    float coverage;       // 0 to 1, paint and raster masks may be soft
    double signedDistance;
    Vec2d nearest;
    AreaEntryId sourceEntry;
};

struct AreaProgram {
    std::vector<AreaDef> orderedBottomToTop;
    u32 revision;
};
}
```

`AreaMaskSample::signedDistance` is positive on the inside for Include boundaries and positive on the outside for Exclude boundaries after orientation normalization. The common query wrapper also returns `incDist` and `excDist` in the candidate's aggregate record. `+inf` means no boundary of that side exists.

### 4.1 Max-layer structures

The Max adapter owns `TYPE_INODE_TAB` references for surfaces, area nodes, linked Forest objects, and ForestSets. It resolves groups and layer membership on the main thread. `SceneSnapshot` contains copied meshes, material IDs, UV channels, shape tessellations, transforms, and immutable upstream `PublishedPopulation` handles. No worker receives an `INode`, `ObjectState`, `ShapeObject`, or ParamBlock2 pointer.

`Get From Forest` is stored as a reference to a source Cyrus object plus a mode flag. It is not flattened into authored surfaces. At snapshot time, the source's published surface entry IDs expand into `SurfaceRef` records. This preserves sharing and lets the source update all consumers.

## 5. Surface cache and surface hit algorithms

### 5.1 Cache key and lifecycle

The global `SharedCacheRegistry` receives a `SurfaceAccel` key:

```cpp
struct SurfaceAccelKey {
    NodeSnapshotId node;
    u64 geometryVersion;
    u64 topologyVersion;
    u64 transformVersion;
    u32 uvChannel;
    u32 materialVersion;
};
```

The value owns a triangulated mesh in surface local coordinates, a BVH or uniform grid, per-face normals, material IDs, UVs, border-edge metadata, and bounds. World and FL transforms are applied at query time through snapshot matrices, so two Cyrus objects can share the same geometry accelerator even when their local frames differ. If profiling shows transformed BVHs outperform this policy, add a derived transform-specific node without changing authored state.

Max geometry notifications increment the relevant version. A topology or UV change invalidates the acceleration structure and any virtual boundary. A transform-only change can retain topology data but invalidates transformed bounds and any raster masks that depend on the transform. The registry is ref-counted and LRU-managed under the 00 architecture's memory cap. Auto rebuild is an evaluation policy, not a second source of truth: manual update can keep the old published result until requested, while Render forces an up-to-date cache.

**Why shared caching is required:** the documented Forest behavior is that terrain processing is shared by Forest objects. Building one triangle accelerator per Cyrus object would make a scene with many scatter layers scale with layer count rather than terrain complexity.

### 5.2 XY mode

S1 supplies a candidate in Forest-local XY. For each surface entry, transform the candidate's ray origin and direction into surface-local space. The direction is the surface object's local negative Z, as specified by Forest behavior. Start from the surface local bound maximum plus a numerical pad and cast downward. Use the `SurfaceAccel` to enumerate all ray hits, not just the first, because stacked surfaces are a supported Cyrus design.

The per-candidate hit procedure is:

```cpp
std::vector<SurfaceHit> hitsForXY(const CandidatePoint& c,
                                  const SurfaceRef& surface,
                                  const SurfaceParams& p,
                                  const SurfaceAccel& accel) {
    RayFL ray = makeForestLocalRay(c.xy, surface, p); // local -Z of surface
    auto raw = accel.intersectAll(ray, p.backFace);
    std::vector<SurfaceHit> out;
    for (const RawHit& h : raw) {
        if (!acceptFaceNormal(h, ray, p.backFace)) continue;
        SurfaceHit sh = interpolateHit(h, surface, c);
        sh.slopeDeg = degrees(acos(clamp(dot(sh.normalFL, Vec3d{0,0,1}), -1, 1)));
        sh.altitude = float(sh.flPos.z);
        sh.backFace = dot(h.normalSurface, ray.dir) > 0;
        out.push_back(sh);
    }
    stableSort(out, [](const SurfaceHit& a, const SurfaceHit& b) {
        return std::tie(a.rayT, a.surfaceEntry, a.faceIndex) <
               std::tie(b.rayT, b.surfaceEntry, b.faceIndex);
    });
    for (u32 i = 0; i < out.size(); ++i) out[i].layer = i;
    return out;
}
```

The default [DESIGN] policy is FrontOnly: accept a face only if its normal faces the incoming ray according to the same winding convention used by the snapshot. DoubleSided accepts either orientation, and Explicit allows the area or surface to choose. This is not asserted to match Forest because its exact policy is [OPEN]. A diagnostic count reports rejected back faces and missed candidates.

The default multi-hit policy is one hit per surface entry, then one candidate record per accepted layer. If the same surface object has multiple coplanar or nearly coincident hits, deduplicate hits with a distance epsilon proportional to scene extent. Across distinct surfaces, preserve every layer. If an old compatibility preset requests nearest-only, select the nearest hit per XY coordinate after all surfaces are sorted by stable entry ID, but do not use this as the default because it destroys stacked-floor support.

If `randomizeStacked` is false, all layers share the normal `StableKey` with `KeyParts.layer = 0`, so transform and model random values match at the same XY. If true, `KeyParts.layer = hit.layer` and the layer is incorporated into every purpose-specific random lookup. Do not include a floating ray distance in the key. It is unstable under tiny mesh edits. Surface entry ID and hit order supply stable identity.

The hit record stores face index, barycentrics, UVW, material ID, normal, position, and slope. Every later stage reads this record. No later stage re-rays the surface.

### 5.3 UV mode

UV mode generates in a surface's selected UV channel. Build a UV acceleration index per surface cache: each triangle contributes a UV triangle, with a robust point-in-triangle test and a list of candidates for overlapping UV triangles. S1's Image generator can emit a normalized `(u,v)` sample from the distribution map. For non-Image generators, the Surface query converts the source point or linked position to a UV sample only when Link to Surface is enabled and a valid inverse mapping is available.

For every UV sample, enumerate UV triangles containing the point, compute barycentric coordinates in UV space, and interpolate the 3D position, normal, material ID, and world transform from the source triangle. UV seams remain separate hit records. Degenerate UV triangles are ignored and counted. Overlapping UVs produce multiple hits and follow the same layer rules as XY.

Area masks in UV mode are evaluated in a projected 2D plane selected by `AreaCommon.projectAxis`. Let `a` be the selected Forest-local axis and `b,c` the remaining axes. Project a surface point with `(dot(p,a), dot(p,b), dot(p,c))` and use `(b,c)` as area coordinates. This is a deterministic interpretation of Project Axis; it also makes the axis explicit when UV geometry is vertical. An area shape is transformed into the same plane before testing. Changing Project Axis invalidates S1, S3, S4, and S8 because it changes generation coordinates, boundary distances, and paint projection.

**Why UV is not a ray cast:** a ray cast assumes one global projection and misses vertical or folded surfaces. UV interpolation follows authored parameterization, at the cost of UV seams, overlap ambiguity, and distortion. The UI must warn about missing or degenerate UVs.

### 5.4 Direction and tangent frame

Let `n` be the normalized hit normal in Forest-local space. Direction is a signed integer `d` in -100 to 100. The default [DESIGN] blend is:

```cpp
float t = float(d) / 100.0f;
Vec3d target = normalize(t >= 0 ? lerp(n, Vec3d{0,0,1}, t)
                               : lerp(n, Vec3d{0,0,-1}, -t));
```

At 0 the target is the normal. At +100 it is Forest-local Up and at -100 it is Forest-local Down. If a compatibility test demonstrates that Forest blends the normal and an axis differently, change this formula under `algoVersion`; do not silently change old scenes.

Construct a tangent frame from a preferred Forest-local axis projected into the plane perpendicular to `target`. If the preferred axis is nearly parallel to target, fall back to the next axis. Normalize with a Gram-Schmidt step and derive bitangent by cross product. Store the frame transiently for S7. To avoid roll jumps between neighboring triangles, choose the sign that maximizes dot product with the previous tile frame, or use a deterministic sign based on the candidate's tile coordinate when no neighbor is available. The sign is not random and must not depend on thread order.

When Scale to fit sloped areas is on in XY mode, force target to `n` and calculate the projection compression correction:

```cpp
float denom = max(1e-5f, abs(dot(n, Vec3d{0,0,1})));
float widthScale = clamp(1.0f / denom, 0.25f, 8.0f);
scale.x *= widthScale;
scale.y *= widthScale;
```

This is a [DESIGN] approximation of the documented slope-spacing correction. Clamp limits prevent near-vertical noise. UV mode ignores Scale to fit and never overrides Direction, matching the documented scope. A compatibility scene must measure the exact factor and update the algorithm version if needed.

### 5.5 Link to Surface and Place Items

For Image mode, surface resolution is part of the normal XY or UV path. For Path, Reference, Particle, and Manual modes, `linkToSurface` controls whether S2 replaces the source item's position along the selected surface direction. When true, preserve the generator's XY or UV-aligned source coordinates but replace the surface axis with the hit position and retain source offset. When false, use the surface only for color, material, filtering, or area tests and keep the source position. For Custom Edit, the UI exposes Link to Surface and Place Items: Link to Surface updates newly placed items from PainterInterface hits; Place Items commits a manually picked position when linking is off. Existing manual transforms are not silently moved when a user toggles the control; the toggle affects subsequent placement unless an explicit Reproject command is used.

## 6. Stage S3: the ordered Area Program

### 6.1 Contract and proposed overlap policy

S1 produces candidate records. S2 may produce one or more records per candidate, with `areaIndex` initially identifying the S1 generating Area and `surfaceId` identifying the hit substrate. S3 evaluates the Area Program from bottom to top. Each Include generates eligibility for points in its mask. Each Exclude culls items generated by lower areas only. The lower-area provenance test is `candidate.areaIndex < currentAreaIndex`, not an inferred geometric comparison.

The proposed default for overlapping Includes is **union without duplication**: an item is eligible if any lower Include contains it, but a coordinate is generated only once by S1. The first Include that accepts a candidate becomes its `includeOwner`; later Includes may contribute falloff and model restrictions only if they explicitly match that candidate. This avoids coplanar duplicates and aligns with the research warning that overlapping Includes should be avoided. It is a [DESIGN] policy and remains [OPEN] for Forest Lite testing.

An Exclude is applied only if `candidate.areaIndex < currentAreaIndex` and the candidate lies in the Exclude mask. It cannot delete an item generated by a later area. This means users must place an Exclude above the Include it cuts, matching documented list behavior. A later Include does not resurrect an item already flagged by an Exclude: the candidate remains owned by its original lower Area and `F_ALIVE` is cleared. A future compatibility mode could re-add after a later Include, but it is not proposed because it makes list order hard to reason about.

```cpp
void AreaProgramStage::run(StageContext& ctx, Population& pop) {
    resetAreaOutputs(pop); // preserve provenance, clear S3 flags only
    for (u32 ai = 0; ai < ctx.params.areas.orderedBottomToTop.size(); ++ai) {
        const AreaDef& area = ctx.params.areas.orderedBottomToTop[ai];
        if (!area.common.on) continue;
        parallel_for_chunks(pop, [&](u32 i) {
            if (!pop.surfaceValid[i]) return;
            AreaMaskSample m = queryArea(area, pop.surfaceHit[i], ctx);
            if (!m.inside && m.coverage <= 0) return;
            if (!passesAreaMaterial(area, pop.matId[i])) return;
            if (!passesSurfaceFilters(ctx.params, pop, i)) {
                pop.flags[i] &= ~F_ALIVE;
                pop.flags[i] |= F_CULL_FILTER;
                return;
            }
            if (area.common.op == AreaOp::Include) {
                if (pop.areaIndex[i] <= ai && !pop.hasInclude[i]) {
                    pop.hasInclude[i] = true;
                    pop.includeOwner[i] = area.common.entryId;
                }
                contributeDistances(pop, i, area, m);
            } else if (pop.areaIndex[i] < ai && pop.hasInclude[i]) {
                pop.flags[i] &= ~F_ALIVE;
                pop.flags[i] |= F_CULL_FILTER;
                pop.excludeOwner[i] = area.common.entryId;
                contributeDistances(pop, i, area, m);
            }
        });
    }
    for_each_item(pop, [&](u32 i) {
        if (!pop.hasInclude[i]) pop.flags[i] &= ~F_ALIVE;
    });
}
```

The pseudocode's `pop.areaIndex` is provenance from S1, while `includeOwner` is an S3 extension. If existing `Population` lacks these fields, add them as transient checkpoint fields and note the extension in the implementation. S3 does not compact or erase items.

For a candidate generated by a distribution mode that has no Include entries at all, use an implicit full-domain Include [DESIGN], subject to the surface Area On toggle and surface filters. This preserves the common workflow of assigning only a surface. If at least one Include is On, the implicit full domain is disabled.

### 6.2 Area common behavior

`Select Models` is evaluated after model selection in the conceptual pipeline, but S3 records an allowlist on the item. S6 resolves `geomId`; if the selected model is not in the Area's allowlist, S6 sets `F_CULL_FILTER`. To avoid an area changing the random model seed, model restriction filters the result rather than drawing a different random number. If no allowed model exists, report a diagnostic and cull.

`Override Distribution Map` stores map, Scale, and Threshold. S3 does not sample a Max map on workers. S0 bakes it to a `MapSampler`, and S3 samples using the candidate's generator coordinates. `mapScale` multiplies the map coordinate around the area origin; Threshold is a binary test unless the generator's density mode requests a continuous value. Map overrides are cached by map version, time, resolution, area transform, and channel.

`Material ID` is a face filter, not a render material assignment. Empty list means all IDs. A nonempty list matches `pop.matId` exactly. In UV mode, material comes from the interpolated surface triangle, even when the UV point crosses a seam.

### 6.3 Area types and exact tests

#### Spline area

L3 tessellates a Max shape into planar polylines, retaining sub-spline IDs, closure flags, and transform. In active area coordinates, a closed spline uses a winding-number point-in-polygon test. Boundary points use a consistent half-open edge convention to avoid double ownership. An open spline uses minimum point-to-segment distance.

`Force Open Splines` treats closed and open inputs as paths and always applies Thickness. The exact Thickness interpretation is **[OPEN]**. Proposed default: the UI value is a radius, so a point is inside when distance <= Thickness. A compatibility option `ThicknessIsFullWidth` divides the value by two. The option must be serialized so a scene does not change when a future default changes.

`Separate Sub-Splines` evaluates each sub-spline independently and includes the sub-spline identity in source metadata. It does not duplicate S1 coordinates. A closed sub-spline's orientation is normalized by signed area; holes are represented by winding orientation if the snapshot says the shape uses holes, otherwise the UI reports an ambiguous contour.

#### Object area

Object Areas are Exclude-only. Build a `RasterMask` in world XY by projecting source triangles along world Z. The 512 default is documented. Clip triangles whose relevant vertices are above `Top Limit`; if the source spans both sides, rasterize only the portion at or below the limit. Resolve coverage conservatively: a pixel is occupied when any projected triangle overlaps it. Apply Scale by a signed morphological dilation around the occupied mask. Scale 1 leaves it unchanged; below 1 erodes toward the object; above 1 dilates away from the object. A distance transform is preferable to repeated binary morphology because it supports fractional scales and stable sampling.

Sample at the candidate's world XY, then require the object's projection and the candidate's surface hit to be compatible with world-Z semantics. This is deliberately not a 3D volume. A vertical wall can have a narrow footprint, matching the documented projection limitation. Cache key includes source node version, transform, resolution, Top Limit, and Scale.

#### Forest area

Forest Areas are Exclude-only and reference another Cyrus object's `PublishedPopulation`. Dependency evaluation comes from the 00 architecture. Detect cycles at assignment. For Sphere, build a spatial hash of source item centers and query a radius from each source model collision radius times area Scale. For Mesh, use the source object's renderable geometry or a derived projected mask at the configured resolution; source items with no render geometry are skipped with a diagnostic. Mesh is slower but more accurate.

The query returns the nearest source item distance and an inside result. If source population version changes, invalidate the Forest Area mask. The mask never holds a pointer to a mutable upstream population.

#### Surface area

A Surface area uses the same `SurfaceAccel` and surface hit. If On and Include, a candidate is inside when its accepted hit belongs to the surface entry and lies within the derived virtual boundary. If On and Exclude, it excludes candidates whose hit is on that surface. The virtual boundary is built once from edges incident to exactly one used triangle, projected into the active XY or Project Axis plane, chained into loops, and simplified only within a configured geometric tolerance. Self-intersections, open chains, and multiple loops produce diagnostics. An explicit Spline area remains the recommended correction.

Do not use the entire surface bounds as its boundary. A terrain mesh often has large empty bounding-box regions. Surface placement can still use the surface when `surfaceAreaOn` is false.

#### Linked area

A Linked area references a source Cyrus object and a source Area entry ID. At S0, resolve the source Area's type-specific parameters and immutable geometry or mask revision. The child inherits Spline Thickness, Object raster settings, Forest Shape, and equivalent type parameters. The child has local common properties: On, Include or Exclude, Select Models, area Scale, map override, Material ID, Falloff Affect, Invert Curve, Boundary Checking, Project Axis, Randomize Stacked, and Separate Sub-Splines.

A linked Object area remains Exclude-only. A link to a source Paint area reads its published paint coverage and does not copy strokes. Source edits invalidate consumers through dependency versions. A cycle is rejected when assigned.

#### Paint area

S3 calls the existing `PaintField::coverage(surfacePoint)` interface. It accepts a soft coverage in 0 to 1, where Include tests coverage against the area threshold and Exclude tests the same field for removal. It also obtains distance-to-boundary metadata where the paint field can provide a signed distance or certified contour. Paint requires an XY surface for Forest-compatible mode, while Cyrus also permits UV projection when Project Axis is fixed before painting. The detailed representation, pressure, dirty regions, and conversion operations are in `05_FALLOFF_PAINT.md`.

### 6.4 Filters

S2 computes altitude in Forest-local coordinates by default. A scene option can request world Z [DESIGN], but the choice must be fixed per object and serialized because a rotated Cyrus node makes them differ. With Altitude Limited, require `Bottom <= altitude <= Top`, after normalizing reversed UI inputs. Slope is degrees from the Forest-local up axis to the hit normal. The default inclusive test is `slopeMinDeg <= slope <= slopeMaxDeg`. Material ID filters happen after the hit is selected and before falloff.

A failed filter clears `F_ALIVE` and sets `F_CULL_FILTER`. It does not erase the record, preserving stage statistics and deterministic compaction. Filters are independent of area falloff: an item outside a hard range never receives a partial density factor.

## 7. Stage S8: boundary checks

S8 runs after S6 and S7 because Size needs the chosen model dimensions and final scale. Point can be evaluated earlier, but keeping all boundary modes in S8 gives one diagnostic and cache contract. The boundary service accepts a point in active area coordinates and returns inside, signed distance, nearest boundary, and edge loop ID.

### 7.1 Point

Point tests the item pivot. If the pivot is outside the owning Include boundary, or inside the active Exclude boundary, set `F_CULL_BOUNDARY`. Point allows footprint overlap and therefore can show cut-off geometry. For a candidate affected by multiple includes, use the include owner's boundary for the hard check and the union boundary for diagnostics.

### 7.2 Size

The footprint is the item's oriented width and depth after S7 scale, expanded by collision radius. Let model width and depth be `w,d`, scale be `sx,sy`, and collision radius be `r`. The proposed conservative radius is:

```cpp
float footprint = 0.5f * hypot(w * abs(sx), d * abs(sy)) + r;
```

Query the boundary signed distance at the pivot. Require `distance >= footprint` for an Include and `distance >= footprint` from the outside of an Exclude. For a spline corner or narrow corridor, optionally test the four oriented footprint corners plus the center; the conservative circle is the default because it is deterministic and avoids orientation-dependent edge flicker. A future exact mode can use support points. This implements the documented use of width and Collision Radius while acknowledging the private shape test is unknown.

If no finite boundary exists, Size reduces to Point. If the boundary is self-intersecting, mark the Area diagnostic and use the safest loop result, not an uninitialized distance.

### 7.3 Edge

Edge never culls the whole item in S8. It sets `F_EDGE_CLIP` when the transformed item's render elements straddle an Include or Exclude boundary. Store an `EdgeClipRecord` containing boundary ID, element IDs, and the plane or distance field needed by the renderer. Render-time adapters in 09 trim or opacity-mask elements. The viewport may show the whole item and an optional debug overlay, matching documented limited preview. Unsupported renderers fall back to Size with a warning, but the authored mode remains Edge.

Edge requires per-element geometry metadata and material grouping. Never approximate it by deleting the instance: that turns a clean perimeter into a hole and loses the documented behavior.

### 7.4 Distance outputs

For every surviving item, compute `incDist` and `excDist` as distances to the nearest applicable Include and Exclude boundary. Include distance is `+inf` when the candidate has no finite Include boundary. Exclude distance is `+inf` when no Exclude applies. A boundary query returns unsigned distance plus side; normalize to the channel convention. S4 uses these channels for its ranges. For Paint, use the field's sparse signed distance to its coverage iso-contour, or a contour fallback.

## 8. Pipeline integration

### S2 Surface resolve

Reads: S1 `pos` XY, surface refs, `SurfaceAccel`, surface mode, UV channel, back-face policy. Writes: `pos.z` or full UV-resolved position, `normal`, `slopeDeg`, `altitude`, `matId`, `uvw`, `surfaceId`, transient `surfaceHit`, tangent frame, and layer. It sets no final cull flag for misses until the stage reports `F_CULL_FILTER` or an explicit invalid-surface diagnostic. A miss clears `F_ALIVE` and increments `stats.surfaceMisses`.

S2 cache key is the tuple of candidate source revision, surface list revision, mode, UV channel, transforms, and surface acceleration revisions. A surface geometry edit dirties S2 and all downstream stages. Direction changes do not require re-hit and begin at S7, except fit-slope toggles which affect scale and start at S7. Back-face changes start at S2.

### S3 Area Program

Reads: surface hit, area snapshots and masks, candidate provenance, map samplers. Writes: `F_ALIVE`, `F_CULL_FILTER`, `incDist`, `excDist`, include owner, exclude owner, model allowlist, and transient area coverage. Object and Forest raster masks use `SharedCacheRegistry`; linked and Forest dependencies include upstream population versions in the key. Area geometry edits dirty S1 if they change the generator domain, otherwise S3. A Project Axis change dirties S1 in UV mode and S3 in all modes.

### S8 Boundary

Reads: chosen model bounds and collision radius, final transform scale, boundary services, area ownership, and Project Axis. Writes `F_CULL_BOUNDARY`, `F_EDGE_CLIP`, and edge records. Boundary geometry changes dirty S8 and downstream render only, but an Include shape that defines S1 generation must dirty S1 through S8. Geometry dimension edits dirty S6 onward and S8. Boundary mode changes begin at S8.

All stages process tile chunks. Surface BVH queries are read-only and thread-safe. Raster masks are immutable after cache publication. S3 area order is evaluated in a fixed loop; work inside one area is parallel. Results merge in tile index then StableKey order.

RNG purposes are stable and area-independent: `AreaMapJitter`, `SurfaceLayer`, and `BoundaryTieBreak` are keyed by `StableKey`, area entry ID, and explicit purpose. Do not call a mutable RNG stream while traversing areas.

## 9. 3ds Max integration

The Max layer implements `CyrusScatterObject : GeomObject`, `ClassDesc2`, and ParamBlock2 entries as described by 02. Surface and area tabs use stable IDs in addition to UI order. Add opens a node picker restricted to mesh or compatible shape types. Add Multiple uses a selection dialog and writes one undoable transaction. Get From Forest accepts a Cyrus object reference and subscribes to dependency notifications. ForestSet-like collections accept a Set node and preserve live membership rather than copying nodes.

Shape extraction uses a main-thread snapshot builder. Use SDK mesh and shape APIs already verified by the project. Do not invent method names: where a specific intersection overload is required, verify the installed 3ds Max SDK headers. The worker receives triangles, UVs, material IDs, and matrices only.

Area list controls are a reorderable Qt model. Each row displays On, type icon, Name, Include or Exclude, source node, and warning badges for invalid UVs, unsupported combinations, or a cycle. Add Spline, Add Object, Add Forest, Add Paint, Add Linked Areas, and Add Surface are explicit actions. Move Up and Move Down update the ordered ID array and issue one `D_AREA_ORDER` invalidation. Delete removes the area definition but retains its immutable ID counter. Selecting a row exposes common properties and a type-specific panel. A surface row in Areas links to the corresponding Surface entry rather than duplicating settings.

Notifications from referenced nodes mark the appropriate DirtyBits group. A surface geometry notification invalidates shared cache data and all dependent objects. A source Cyrus population publication invalidates Forest Areas and linked areas. Manual Update may hold the old published population until the user commits update; Render forces synchronous rebuild.

## 10. Edge cases and failure modes

* **No surfaces:** S2 reports a missing substrate. Image mode produces no survivors unless a generator explicitly does not require surface placement and Link to Surface is off.
* **Multiple surfaces with identical hits:** deduplicate by position and normal epsilon only within one surface entry. Preserve distinct entry IDs.
* **Back-face ambiguity:** count rejected back-face hits. Offer DoubleSided as an explicit option and flag that it diverges from unverified Forest behavior.
* **Stacked surfaces:** preserve layers and layer keys. Warn when Falloff or Edge is enabled if the compatibility profile says those features are uncertain with stacks.
* **UV overlap:** return all containing triangles. If `maxUvLayers` is exceeded, retain the nearest deterministic subset and report a limit warning. Never choose by thread completion.
* **UV seam:** each seam side is a separate face hit. Paint storage remains surface-anchored and per face, not a stitched UV bitmap.
* **Degenerate UV triangle:** skip it and increment `uvDegenerateCount`.
* **Open surface border:** virtual boundary has no closed loop. Mark it invalid and require an explicit Spline for falloff and boundary checks.
* **Nonuniform or mirrored transforms:** preserve double-precision matrices and correct normal inverse transpose. A negative determinant flips winding; normalize according to the chosen back-face policy.
* **Altitude Top below Bottom:** swap for evaluation and show a UI warning; preserve authored values for round-trip.
* **Empty Material ID list:** all IDs. Unknown IDs are simply no matches.
* **Object raster at large extents:** use per-tile double bounds and clamp resolution. Avoid world-space integer overflow.
* **Forest dependency cycle:** refuse the assignment at the Max layer and retain the previous valid reference.
* **Deleted source:** area becomes Off with a visible missing-reference badge; authored settings remain.
* **Overlapping includes:** union without duplication by default, log a compatibility warning, and expose a test-only mode for duplicate generation.
* **Boundary self-intersection:** use a robust winding implementation, mark diagnostic, and recommend an explicit spline.
* **Boundary too small for Size:** cull deterministically. Do not shrink the model to fit.
* **Edge unsupported by renderer:** fall back to Size at output and warn once per render.
* **Paint coverage unavailable:** treat a Paint Include as empty and Paint Exclude as no-op, with a stale-data diagnostic. Never interpret missing data as full coverage.

## 11. Performance and memory

Targets are [DESIGN] engineering goals, not measurements. On a 16-core workstation:

* Resolve 1M XY candidates against a cached 2M-triangle terrain in under 250 ms after BVH warm-up.
* Resolve 1M UV samples against a cached UV index in under 300 ms, excluding cache build.
* Build a 512 by 512 Object or Forest raster mask in under 20 ms for ordinary 100k-face sources.
* Evaluate 1M candidates against ten simple area masks in under 100 ms after masks are cached.
* Keep per-item transient S2 and S3 metadata below 64 bytes beyond the 00 Population fields.
* Make a surface cache reusable across ten objects without copying triangle positions.

The dominant traps are ray casting one candidate at a time without a batch BVH, rebuilding raster masks for every object, retaining all UV overlap candidates when a scene has pathological seams, and using a global mutable RNG. Batch queries by tile, use cache-local arrays, and merge in deterministic order. A 512² bitset is about 32 KiB before distance fields, but a float distance transform is about 1 MiB. Keep distance fields optional when no falloff or Size check requests them.

## 14. Architecture feedback

`00_ARCHITECTURE.md` correctly places surface resolution in S2, area semantics and filters in S3, and boundary checks in S8. Two small extensions are required:

1. Add transient `surfaceHit`, `hasInclude`, `includeOwner`, `excludeOwner`, per-item model allowlist metadata, and optional edge records to the Population checkpoint type. These are evaluation outputs, not authored truth.
2. Add `D_AREA_ORDER`, `D_SURFACE_LIST`, `D_SURFACE_PARAMS`, and `D_SURFACE_FILTER` to the DirtyBits mapping. A Project Axis change in UV mode must dirty S1 through S8, while a boundary mode change starts at S8.

The stable `KeyParts.layer` field already provides the right extension for stacked surfaces. The existing `SharedCacheRegistry` is also sufficient: `SurfaceAccel` and `RasterMask` keys need the explicit geometry, topology, UV, transform, resolution, Top Limit, and scale components described above. No change to the core layering or deterministic merge rule is needed.

## 15. Summary of implementation decisions

Cyrus stores live surface references and ForestSet-like collections, but snapshots expand them into immutable compatible inputs. Surface acceleration is global and versioned. XY casts along surface-local Z and retains deterministic stacked hits. UV samples the selected UV channel and uses a Project Axis for area projection. Direction uses a declared blend and a stable tangent frame; Scale to fit is XY-only and normal-aligned. The Area Program executes bottom to top, with Include union without duplicate generation and Exclude culling only lower candidates by `areaIndex`. Spline, Object, Forest, Surface, Linked, and Paint areas each have explicit tests. S8 checks Point, Size, and Edge, with Edge flagged for render-time trimming. All unknown Forest behavior remains labeled [OPEN] and receives a Forest Lite test rather than an invented compatibility claim.
